Rachana · the screen grammar

A screen is a paragraph, not a project.

Rachana (रचना, composition) is Drishti's screen grammar. Each product family gets a Sutra: a short, versioned YAML file written in it. It names the key figures, the panels, the bindings and the function keys. It holds no code and no pixels. Wherever it says infer: true, the inference engine reads the shape of the data and completes the layout.

If a product has no Sutra at all, it still renders on day one: inference turns arrays into tables, term structures into curves and identifiers into links.

  packs/finance/sutras/rates/irs-vanilla.v3.yaml
sutra: irs-vanilla
version: 3
match: { kind: trade, where: "productType == 'IRS'" }
strip:
  - { label: Notional (USD), bind: $.notional, fmt: amount0 }
  - { label: MTM (USD), bind: $.mtm, emphasis: true }
panels:
  - { id: legs, key: F2, kind: tabs, infer: true }
  - { id: flows, key: F3, kind: table, rows: $.cashflows }
  - { id: curve, key: F4, kind: line, source: link($.curve) }
  - { id: refs, kind: links }       # every id becomes a door
The view pipeline

Seven stages. Every view. Every tick.

Every request goes through the same stages. Layouts are cached by the shape of the data, so the cost of inference is paid once per shape; warm requests only bind values.
