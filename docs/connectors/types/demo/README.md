# The demo connector

Built-in connector `demo` (`plugins/drishti-connectors`, package `plugin.demo`: `DemoSourcePlugin`, `DemoTicker`, `DemoWalk`): the samples each enabled pack ships in
`config/packs/<domain>/<pack>/samples/`, so a server with nothing installed shows working screens. It is the `default-route`, tried after a
kind's own route. **Switch it off in production** (`DRISHTI_DEMO_ENABLED=false`): it serves made-up data under real-looking names.

## What it reads

At start it reads, for each folder in `dirs` (filled by the packs, most general first), `catalog.jsonl` and each kind's JSON Lines file,
once, into memory: the documents, each document's `walk` and a type-ahead index of every catalogue entry. It never reads the folders
again (an edited sample needs a restart). Reads are map lookups; type-ahead searches ids, titles and subtitles; reverse lookups scan
every document held at every depth for a value equal to the target id. Live samples move a little every `tick-ms` (400) while someone
watches them. It runs only **as itself** (`drishti.sources.plugins.demo`), never as a named connector, serves every kind, and is not
dated: every business date gets the same document.

## Data structure

The samples folder of a pack:

```
config/packs/<domain>/<pack>/samples/
├── catalog.jsonl     {"kind": "bond", "id": "BND-BRVERD054608", "title": "BND-BRVERD054608", "subtitle": "Bond (security master) · …"}, one a line
├── <kind>.jsonl      one document a line, in the catalogue's order (above about 50 MB: <kind>.part-001.jsonl, …)
└── …                 the older layout, <kind>/<id>.json, is still read
```

- **Id rule:** the catalogue entry's `kind` and `id`; only listed entries are loaded; a JSON Lines line is matched to its entry by
  position, else by its id value. An entry whose kind or id would leave the folder (`../`) is skipped. `title` and `subtitle` are what
  the type-ahead dropdown shows.
- **Document:** the entity as its system of record holds it (UPPER_SNAKE, nested lists inside, e.g. a trade's `LEGS` → `CASH_FLOWS` →
  `RESETS`, `EVENTS`), plus a `_meta` block the connector removes and turns into provenance:

```json
{"VALUATION_ID": "TVAL-1000001", "TRADE_ID": 1000001, "COUNTERPARTY": "CP-HARBORPT", "MTM": 4121280, "PNL_1D": -277804, …,
 "_meta": {"source": "risk-engine", "generation": 1, "live": true,
           "walk": {"MTM": 9922, "derive": [{"set": "PNL_1D", "expr": "$.MTM - 4399084"}]}}}
```

| `_meta` key | Becomes |
|---|---|
| `source` | `provenance.source`: the name users see (`endur`, `risk-engine`, `md-hub`), not `demo` |
| `generation` | `provenance.generation` (truncated to a whole number); each tick adds 1 |
| `live` | `provenance.live`; only live samples tick and can be subscribed to |
| `walk` | the fields that move on each tick (`{FIELD: step}`, coherent groups, `derive`, `append`); optional ([Live ticks](#live-ticks)) |

The `_meta` keys stay lower case; the fields and paths inside a walk are the document's (UPPER_SNAKE). A document without `_meta` still
loads: empty source, generation 0, not live. A document that is not a JSON object stops the connector from starting. Trades carry
`_meta` without `live` (a trade's terms do not move during the day); each trade's **valuation** (`trade-valuation`) ticks its `MTM` and
`PNL_1D`.

## Examples

```yaml
# kernel/drishti-server/src/main/resources/application.yaml (shipped)
drishti:
  sources:
    default-route: demo                     # tried after a kind's own route
    plugins:
      demo:
        enabled: ${DRISHTI_DEMO_ENABLED:true}

# application.local.yaml: freeze or slow the ticks
drishti:
  sources:
    plugins:
      demo:
        settings:
          ticking: false        # freeze every document (screenshots, golden tests)
          tick-ms: 1000         # tick once a second instead of every 400 ms
```

It has **no connector file**: connector files in `config/connectors/` are for the connectors that read your systems. Switch it off for
one start, or for good:

```bash
DRISHTI_DEMO_ENABLED=false java -jar kernel/drishti-server/target/drishti-server-*-exec.jar
java -jar kernel/drishti-server/target/drishti-server-*-exec.jar --drishti.sources.plugins.demo.enabled=false
```

The run configuration **Drishti server (demo lakes)** starts with the demo off, so every page reads the lakes `drishti.py lake demo`
built ([../../../guides/DATA_GUIDE.md section 11](../../../guides/DATA_GUIDE.md#11-the-demo-data)); **Drishti server** (and a bare `java -jar`) leaves it on, for what only it
gives: values that tick live (live BI and boards) and screens with no store at all. With the demo off, `default-route: demo` names a
connector that does not run and the router skips it; a kind no other connector (nor the `file` plugin) serves then answers
`DRS-1002 no source serves kind '<kind>'`.

A quick look: `CRV CRV-USD-BASIS <GO>` (a curve whose every row ticks), `FX FX-EURUSD <GO>`, `NSET NS-SUMMIT-NY <GO>`. Provenance shows
the sample's own source:

```bash
curl -s http://localhost:18480/api/v1/entities/trade-valuation/TVAL-1000001/raw | jq -c .provenance
# {"source":"risk-engine","generation":1742,"fetchedAt":"…","live":true,"businessDate":null}
```

Each pack's generators under `tools/packgen/` write its samples (never edit them by hand).

## Troubleshooting

```bash
B=http://localhost:18480/api/v1
curl -s $B/sources -H "Authorization: Bearer $DRISHTI_TOKEN" | jq -c '.sources[] | select(.name=="demo")'
curl -s $B/admin/health -H "Authorization: Bearer $DRISHTI_TOKEN" | jq '.failedToStart'
```

| Symptom | Likely cause | What to do |
|---|---|---|
| `demo` missing from `/sources`, `failedToStart` names it | a `dirs` folder without `catalog.jsonl`, or a sample that is not a JSON object | fix the sample named in the message (regenerate with the pack's generator); restart |
| `demo` missing, no failure | it is off (`DRISHTI_DEMO_ENABLED=false`, the demo-lakes run configuration) | turn it on if you want samples and ticks |
| a pack's samples are not served | the pack is not in `DRISHTI_PACKS`, or its `samples` folder does not exist | enable the pack; check `samples:` in its `pack.yaml` |
| an edited sample shows the old content | samples are read once at start | restart the server |
| a parent's sample shows instead of the child's (or the reverse) | the later folder in `dirs` wins; folders run most general first | put the override in the more specific pack |
| a live view does not tick | `_meta.live` is false (trades: watch `trade-valuation`), `ticking: false`, the demo is off, or a real stream holds the entity and ticks instead | set `live: true`; check the settings; check `provenance.source` |
| a walked field does not move | the path leaves the document or ends at something that is not a number, or the sample is not live | check the path against the sample's UPPER_SNAKE names (`TOP_TRADES.0.MTM`) |
| a detail list does not follow its headline | the sample walks the headline alone (the plain `{FIELD: step}` form) | use a [coherent walk](#coherent-walks-a-group-that-moves-together); `DemoPackWalksTest` flags a declared dependent that never moves |
| a `derive` or `append` entry has no effect | its expression does not parse, or names a field the sample lacks: that entry alone is skipped | run `DemoPackWalksTest` (it parses every expression and resolves every path of every shipped sample) |
| real ids answer with sample data, or an old picked date shows a sample | the demo is on beside the lakes | `DRISHTI_DEMO_ENABLED=false` |
| `DRS-1002 no source serves kind 'x'` after switching it off | the demo (and `file`) served that kind | configure a connector for the kind |

Health is always `UP` while running; it reports no cache figures and a purge does nothing. `lastUpdate` is the time of the last tick (or
of start, with `ticking: false`), so a `stale-after` only fires when ticking is off.

## How packs supply samples

A pack does not declare a `demo` connector. Its `pack.yaml` may name its samples folder (`samples: samples`, the default); when that
folder exists, the pack loader adds it to one setting:

```
drishti.sources.plugins.demo.settings.dirs = <packs>/core/samples,<packs>/market-data/samples,<packs>/trading/samples,…
```

The folders are listed **most general pack first** (with `DRISHTI_PACKS=counterparty-risk`, its parents `core`, `market-data` and
`trading` come before it). A sample with the same kind and id in a later folder **replaces** the earlier one, so a child pack overrides
a parent's sample by shipping the same kind and id; type-ahead keeps one entry per entity the same way. Only enabled packs
(`DRISHTI_PACKS`) contribute; a pack switched off for users in Admin → Packs still has its samples loaded (that switch hides kinds, it
does not restart connectors). Setting `dirs` by hand replaces what the packs put there, which is how a site serves a folder of its own
samples. How the samples are generated, and loaded into every real store, is in
[../../../guides/DATA_GUIDE.md section 11](../../../guides/DATA_GUIDE.md#1115-the-samples); the format from a pack author's side is in
[the pack developer's guide](../../../guides/BUILD_GUIDE.md#54-samples).

## Reads and what each costs

| Read | How | Cost |
|---|---|---|
| one entity (`TVAL TVAL-1000001`) | one map lookup; the shared document gets a provenance with the current `fetchedAt` | a hash lookup; no I/O |
| a picked business date | the same document: the connector is not dated | as above; the console says the source keeps no dates |
| type-ahead (`TRD MX-2`) | ids that start with the text (binary search of each kind's sorted ids), then ids that contain it, then titles and subtitles, case-insensitive, up to the limit | a binary search, then scans until the limit |
| search, pick list, derived kind, impact | the engine lists the kind through the same index and reads each document; no promoted columns | one lookup per entity, within `drishti.search.max-scan` (20,000) and its time budget |
| reverse lookup (*Linked entities*) | every document held: of the kind asked, not the target itself, with a value **at any depth** (field, nested field, array element) equal to the target id; sorted by id | a scan of every sample per call |

Other connectors that declare reverse lookups are asked as well and their referrers added.

## Live ticks

A view, live BI visual or board tile on Live subscribes to its entities. The connector accepts a subscription only for a sample whose
`_meta.live` is `true` (otherwise the router tries the next live source); when the last subscriber leaves, the entity stops moving.

With `ticking: true` one task runs at a fixed rate of `tick-ms` on the server's source scheduler. Each run records `lastUpdate`, then for
every live entity with a subscriber computes the next document, stores it **in place of the old one** (`generation + 1`, new
`fetchedAt`) and hands it to each subscriber (one that throws is ignored). A value therefore keeps walking from where it got to until
restart, and every later read, by any user, sees the moved value. With `ticking: false` no task runs: subscriptions are accepted, no
update is sent.

### How a field moves

Steps are draws from a normal distribution (seeded with 42, shared by the connector: repeatable, but dependent on which entities are
watched). In a plain walk (`{"MTM": 9922}`) each named field gets `value + N(0, step)` (the step is the standard deviation, not a
bound). A whole number stays whole when its step is 1 or more; otherwise the result keeps two more decimals than the step has (at least
two): a step of 0.0004 keeps six decimals, so an FX mid moves about a pip a tick. A field may be a **path**: `TOP_TRADES.0.MTM` (names
step into objects, whole numbers into lists, from 0). A path that leaves the document or ends at something that is not a number is left
alone. A live sample without `walk` ticks with an unchanged document and a higher generation (a few built-in walks remain for the
example `finance` pack's camelCase kinds).

### Coherent walks: a group that moves together

A real market moves in groups: when the 10-year rate ticks, the curve, its forwards, its discount factors and its slope tick with it. A
`walk` object says so in the sample, with no code:

| Entry | Form | Does |
|---|---|---|
| a step | `"FIELD": 0.0003` | that one number, by N(0, step) |
| a group step | `"FIELD": {"step": …, "with": […], …}` | ONE draw moves the field **and** every path in `with` |
| `derive` | `[{"set": path, "expr": "…", "places": n}]` | after the steps, recomputes what depends on the moved numbers |
| `append` | `[{"to": path, "key": field, "format": "…", "row": {…}, "keep": n}]` | keeps a time series current |

Steps run first, then `derive` in the order written (a later one sees an earlier one's result), then `append`; an entry that cannot be
applied is skipped and the others still run. Paths add three forms: `POINTS.*.ZERO_RATE` (every element), `HISTORY.-1.MID` (the last
row; `-2` the one before), `POINTS.TENOR=10Y.ZERO_RATE` (the element whose `TENOR` is `10Y`).

| Group option | Default | Meaning |
|---|---|---|
| `step` | required | standard deviation of the one draw |
| `with` | none | paths that move with it: a path, or `{"path": …, "scale": …, "places": …}` |
| `scale` | 1 | each `with` path moves by draw × scale (a decimal rate and the same rate in percent: `scale: 100`; negative moves against); a path's own `scale` wins |
| `shape` | `parallel` | `parallel`: same shift for every element of a `*` path; `twist`: also a tilt from one end of the list to the other |
| `jitter` | 0 | an independent extra draw per element, as a fraction of `step` |
| `mode` | absolute | `rel`: `step` is a fraction, each value moves by its own size × the draw |
| `places` | from the step | decimals kept; a `with` path may set its own |
| `min`, `max` | none | clamp the walked field |

**`derive`** evaluates `expr` for every place `set` reaches (for `POINTS.*.DF`, once per point, that point being the current element).
A name is looked up in the current element, then in the document; `$.NAME` is always the document. The language: numbers, `'text'`,
`+ - * /`, parentheses, comparisons, `test ? a : b`, `*` paths as lists, and the functions `exp ln sqrt abs pow round clamp min max sum
sumpos sumneg avg count tenor noise` (`tenor('1M')` is 1/12; `noise(sd)` is a draw). A number keeps `places` decimals, else the old
value's. `{"set": "LEGS.0.CASH_FLOWS.*.PV", "scaleTo": "$.LEGS.0.PV"}` rescales every number reached so they add up to the target.

**`append`** labels the current time with `format` (a Java `DateTimeFormatter` pattern: `HH:mm`, `yyyy-MM-dd`); a row of `to` with that
label in `key` is updated, else a row is added and the oldest fall off at `keep`. Each `row` field is an expression, `last.NAME` being
the previous version of that row.

The cross-currency basis curve `CRV-USD-BASIS` (`config/packs/banking/market-data/samples/ir-curve.jsonl`), whose `TEN_Y` is a decimal
while its zero rates and forwards are in percent:

```json
"walk": {
  "TEN_Y": {"step": 0.0003, "scale": 100, "shape": "twist", "jitter": 0.15,
            "with": ["POINTS.*.ZERO_RATE", {"path": "POINTS.*.QUOTE", "scale": 1}, "FORWARDS.*.RATE"]},
  "derive": [
    {"set": "POINTS.*.DF", "expr": "exp(-ZERO_RATE / 100 * tenor(TENOR))", "places": 6},
    {"set": "TEN_Y", "expr": "POINTS.TENOR=10Y.ZERO_RATE / 100", "places": 6},
    {"set": "SLOPE_2S_10S", "expr": "(POINTS.TENOR=10Y.ZERO_RATE - POINTS.TENOR=2Y.ZERO_RATE) * 100", "places": 1}
  ]
}
```

One draw moves every zero rate, quote and forward, with a tilt and 15% per-tenor blur; then each discount factor follows its zero rate,
the headline becomes the 10-year point and the 2s10s slope is recomputed. Other ideas, each in a shipped sample:

| Idea | Entry |
|---|---|
| the spread stays constant (fx-spot) | `"MID": {"step": 0.0004, "places": 5, "with": [{"path": "BID", "places": 5}, {"path": "ASK", "places": 5}]}` |
| today's history row follows the price | `{"set": "HISTORY.-1.MID", "expr": "$.MID", "places": 5}` |
| a change against yesterday's close | `{"set": "CHANGE_1D", "expr": "MID / HISTORY.-2.MID - 1", "places": 5}` |
| a P&L against the opening value (trade-valuation) | `{"set": "PNL_1D", "expr": "$.MTM - 4399084"}` |
| a status re-judged against its thresholds | `{"set": "status", "expr": "value >= red ? 'Red' : value >= amber ? 'Amber' : 'Green'"}` |

The specs are never written by hand: `tools/packgen/common/walks.py` builds each kind's walk from the finished sample and every generator
calls it; `python3 tools/packgen/banking/make_data.py --check` fails when the samples differ from what the generators write. What stays
still on purpose (coupon schedules, trade terms, end-of-day risk) is listed per kind in `walks.py` and in
[../../../guides/DATA_GUIDE.md section 11](../../../guides/DATA_GUIDE.md#live-walks-by-kind); `DemoPackWalksTest` fails on a walked headline whose declared
dependents never move and on a walk naming a path its sample lacks.

## Its place in routing

The router ([how a request picks a connector](../../../guides/DEVELOPER_GUIDE.md#how-a-request-picks-a-connector))
tries a kind's route, then the `default-route` (`demo`), then every other connector serving the kind. The demo's manifest lists no
kinds, so it is a candidate for **every** kind and answers "not held" for ids it has no sample of.

| The user asks for | Effect |
|---|---|
| Live | live sources first, the `default-route` last among them: a real stream before the samples, then non-live stores; with no stream, a sample **answers before** the lake for an id both hold |
| a picked date | dated sources first: the lakes answer for the dates they hold; for an older date the sample answers, with the banner *No data held for <date>: the current data of endur, a source that keeps no dates* (the sample's `_meta.source`) |
| ticks | the first live source that **holds** the entity |
| type-ahead, search, reverse lookups | every capable source is asked and results merged: samples appear beside the stores' ids |

## Memory, limits and security

Every document is held parsed in memory for the life of the server (several times its JSON size), beside one type-ahead entry and one
`walk` per sample: start time, heap and each reverse lookup grow with the number of samples; each tick walks only the subscribed
entities. It is read once at start, undated (no `snapshot`/`effective`, no *known at*), has no promoted columns, one tick rate, and
drifts without bound until restart. For a large book use a real store ([../../../guides/DATA_GUIDE.md section 11](../../../guides/DATA_GUIDE.md#11-the-demo-data) builds the
demo lakes).

There is nothing to lose: after start it reads nothing from disk or network. A catalogue entry its kind's file does not hold is
skipped; a sample that cannot tick (a built-in walk meeting a document without its fields) keeps its document while the others tick.

**Security.** It serves made-up data under real-looking names (system names, plausible amounts): on a production server an id the real
store lacks, or a date older than its history, can be answered by a sample. Entitlements and redaction apply as for any source; it uses
no credentials, network or TLS, and reads only the kinds and ids its catalogues list, inside their folders.

## Checklist for production

1. Set `DRISHTI_DEMO_ENABLED=false`, and check `GET /api/v1/sources` does not list `demo`.
2. Give every kind users open a real connector (a route or `kinds`), or the `file` plugin as a fallback; otherwise reads answer
   `DRS-1002`.
3. Change `default-route` if a real connector should be asked second for every kind (with the demo off, `demo` is simply skipped).
4. On a demonstration server that keeps it on, say so on screen, keep its packs to the ones shown, and leave `ticking` on.
5. When writing samples, give each live sample a `walk` with steps sized to the field, and regenerate with the pack's generator.
