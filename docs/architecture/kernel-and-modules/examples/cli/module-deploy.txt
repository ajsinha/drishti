EXAMPLE (design, not built): deploying banking 3.0.1 (an upgrade of 3.0.0) on the 3-node cluster from a script: plan, approve, apply,
status (docs/architecture/KERNEL_AND_MODULES.md section 7.6; placement: examples/site/placement.yaml; the plan file:
examples/site/deployment-plan.json). The Admin page (Admin -> Modules -> Deploy) calls the same API and shows the same plan.

$ export DRISHTI_SERVER=https://drishti-main.bank.internal:18480
$ export DRISHTI_TOKEN=$(secret-tool lookup drishti admin-alice)       # never on the command line

# 1. Plan (alice): changes nothing
$ python3 tools/drishti.py module deploy banking-3.0.1.dmod --placement config/placement.yaml --plan --out banking-3.0.1.plan.json

# 2. Apply (alice) proposes; four eyes
$ python3 tools/drishti.py module deploy --apply banking-3.0.1.plan.json
Proposed dpl-2026-1108-0012 (CHG-2026-1108-0061). Waiting for a second administrator.
$ echo $?
3

# 3. Approve (bob, his own token)
$ DRISHTI_TOKEN=$(secret-tool lookup drishti admin-bob) python3 tools/drishti.py module deploy approve dpl-2026-1108-0012 \
      --reason "Release 2.9.11.i, ticket RISK-4430"
Approved by bob. (The proposer cannot approve: alice's approve would answer DRS-1027.)
