The banking module's source tree as built (docs/architecture/KERNEL_AND_MODULES.md section 8.10): the one module layout. The .dmod
content at the folder's top (as inside banking-1.0.0.dmod), the code as two Maven projects under java/, aggregated by pom.xml.
packaging/dist packs the folder with the module tool (`pack modules/banking --jar drishti-banking.jar --more drishti-compute-banking.jar`).

modules/banking/
├── module.yaml                     the manifest (section 3.3); kernel-internals: java/kernel-internals.txt      → module.yaml (list stamped in)
├── content.yaml                    what the packer brings in: the risk and trading lenses, the four banking guides  never packed
├── packs/                          trading, market-risk, counterparty-risk (kinds, contracts, Sutras, samples)   → packs/
├── console/plugin.yaml             format 2: routes, words, menus                                               → console/
├── data/needs.yaml                 the kinds it reads and writes                                                → data/
├── docs/                           README.md, help.yaml                                                         → docs/
├── java/
│   ├── banking-compute/            artifact drishti-compute-banking: VaR, exposure, FRTB-SA, SIMM, sensitivities → java/drishti-compute-banking.jar
│   ├── banking-service/            artifact drishti-banking: BankingModule, services, storage, API              → java/drishti-banking.jar
│   └── kernel-internals.txt        the kernel packages banking still reaches (BankingReachTest: true, only shrinking)
└── pom.xml                         aggregates java/banking-compute and java/banking-service                       never packed

Former places (before i5): modules/banking/dmod/* (the .dmod content), modules/banking/banking-compute, modules/banking/banking-service
and modules/banking/kernel-internals.txt; moved with `git mv`, history kept.
