"Let everything through" turns the waits off (the server can then run out of memory); "Hold all new heavy work" is for a planned restart: signed-in people keep reading. Either ends by itself and goes back to Automatic.

How it feels

  • One consistent signal everywhere (the banner) and one place for everything you are waiting for (the tray).
  • Feels like a queue: a position and a rough wait; you can leave the page.
  • Good when people start several heavy things at once (month-end).

Trade-offs

  • The "line" is really each browser retrying on Retry-After; positions are estimates and can jump, which people notice.
  • A true server-side queue would hold state while short of memory, against the point of the feature; and across a cluster it needs a shared line.
  • More to build: banner, tray, notes, ordering, and a line on Admin → Health.

When to pick it

  • If waits are expected to be long and frequent (a small server with many users).
  • Can be added on top of A later: A's retry helper feeds the tray.
