Overload defences: option C, busy shown before you clickalternative

The console shows how busy the server is all the time: a small light in the top bar, and on each heavy button (open a date, download, run BI, load) an hourglass with the expected wait, so people choose "when there is room" instead of being refused. The server still decides at the click; small, cheap requests go straight through.

"Let everything through" turns the waits off (the server can then run out of memory); "Hold all new heavy work" is for a planned restart: signed-in people keep reading. Either ends by itself and goes back to Automatic.

How it feels

  • Fewer surprises: the wait is visible before the click, like a "busy" sign on a door.
  • Small, cheap work (a 412-row download) is never held up by a blanket rule.
  • Admin sees a short history, so a rising line is caught before refusals start.

Trade-offs

  • Needs the busy state pushed or polled to every console: more traffic at the worst moment, and a hint that can be ten seconds stale.
  • Still needs A's in-place message for the click that is refused anyway, so it is A plus more.
  • Per-request cost estimates (the 10,000-row rule) are extra design and testing.

When to pick it

  • If refusals turn out to be common in practice: then showing the wait up front saves frustration.
  • The top-bar light alone is a cheap later add-on to A.
