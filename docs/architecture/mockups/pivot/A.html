Scene 2Pivot → Functions → New: the playground for a custom aggregation function

Code Python · kind: mergeable · inputs r, w (float64) · tolerance 1e-12

from drishti_pivot import function, Mergeable import pyarrow.compute as pc @function(name="wavg_return", kind=Mergeable, inputs={"r": "float64", "w": "float64"}) class WeightedReturn: def start(self, params): return {"swr": 0.0, "sw": 0.0} def add(self, s, batch): # one Arrow batch swr = pc.sum(pc.multiply(batch["r"], batch["w"])).as_py() or 0.0 sw = pc.sum(batch["w"]).as_py() or 0.0 return {"swr": s["swr"] + swr, "sw": s["sw"] + sw} def merge(self, a, b): return {k: a[k] + b[k] for k in a} def finish(self, s): return None if s["sw"] == 0 else s["swr"] / s["sw"]
Sandbox: no network, no files, no processes · 1 GB · 30 s a batch · packages: numpy, pyarrow (allowed list)

How it feels

  • Excel's PivotTable, field for field: drag, nest, expand, double-click for rows.
  • Everything Excel gets wrong is visibly right: VaR per cell, ≈ marked, diversification, Others computed.
  • One key for every action; the popover answers "where does this number come from" in place.

Why recommended

  • Nothing new to learn for anyone who has used Excel; adoption first.
  • The beyond-Excel parts sit where Excel's equivalents would be, so they are found.
  • B's command line is always in the bar, and C's compare is the Compare picker.

Trade-offs

  • The right rail takes 330 px; it folds away with F.
  • Explain and what-if open as panels, not side by side (B shows them always).
  • On a phone: the grid's top left and the chart; the field list is desk only.
Mock-up. Design, not built (HOW_IT_FITS.md#a26-the-pivot-engine). Names, numbers, versions and nodes are illustrative. A ≈ figure states its error; a holistic figure is computed from its own members, never from other cells; masks and row rules are applied before anything is grouped.
