What the heap holds

Dates in memory (10 + 1 opening)1,927 MBWhy?Each open date keeps its skeleton on the heap: 175 MB a date at 300,000 positions (the H_book formula, 223 MB, × the 0.785 calibration to the 1M benchmark). 10 dates in memory, plus the one opening while the oldest still has readers: 11 × 175 MB.
Today's intraday layer1,627 MBWhy?117,000 trades changed today (39% of 300,000). Each keeps three float64 vectors of 509 scenarios (difference, P&L, USD P&L): 1,408 MB; the changed books' and nodes' aggregates 183 MB; currency totals 32 MB.
Caches at their budgets402 MBWhy?BI query cache 64 MB, plan answers 50 MB, history 256 MB, VaR answers 32 MB: each at its configured budget (drishti.bi.query.cache-max-bytes, drishti.history.cache-mb…).
Trade rows beyond the measured347 MBWhy?The trade connectors' working set for 300,000 rows a day, above the 20,000 the start heap already holds: 1.3 KB a row (BENCHMARK 8.2).
Everything else (start, users, footers, search)620 MBWhy?The server at start 292 MB, users 123 MB, footer cache 64 MB, search 57 MB, first-open warm-up 83 MB.
Heap after GC4,924 MBWhy?÷ 0.61 for the collector + 1,367 MB of loads = 9.4 GB → 10g.

Disk

Lakes (VaR, intraday, trades)252.7 GBWhy?One year: VaR 105.8, intraday 41.3, trades 105.6 GB.

Caches, BI, logs, dumps64.8 GBWhy?Trade caches 12.5, BI 41.1, logs 1.1, one heap dump 10 GB.

Start the server with

The whole command line, ready to paste (Linux; on Windows drop MALLOC_ARENA_MAX)
MALLOC_ARENA_MAX=2 java -Xmx10g -Xms10g -XX:+UseG1GC -XX:G1PeriodicGCInterval=60000 -XX:MaxDirectMemorySize=256m -XX:TrimNativeHeapInterval=60000 -Djdk.nio.maxCachedBufferSize=262144 -XX:NativeMemoryTracking=summary -XX:MaxMetaspaceSize=512m -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/opt/drishti/data/dumps -Xlog:gc*:file=/opt/drishti/data/logs/gc-%p.log:time,uptime:filecount=5,filesize=20m -Djava.io.tmpdir=/opt/drishti/data/tmp/server -Ddrishti.parquet.footer-cache-mb=64 -Ddrishti.open-dates.net-grace-seconds=120 -jar drishti-server-2.9.10-exec.jar

Step 2 of 4 · Dates in memory and pins as it looked a moment ago: one question at a time, a choice of three, the effect shown at once

How many business dates should stay open at once?
2 datestoday and yesterday · -Xmx7g · RAM 16 GB · older dates reopen in 0.1 s from disk
10 datestwo weeks open · -Xmx10g · the production choice
20 datesa month open · -Xmx13g · RAM 32 GB
Why?Pinned dates never leave; with 0 the protected dates (2) are fewer than hot-dates, so nothing is exceeded.
Why?Each adds a 898 MB hot file under var/hot.
