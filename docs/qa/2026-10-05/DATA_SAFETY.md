## Tested and held

- Explain/About: `GET /views/trade/{id}/explain` for the viewer and the compliance user contains no masked value (text reads "with •••", glossary, panel notes), in either call order (author first, then non-raw: the cache is per user). Pack-less user gets `403 DRS-5002`.
- Ask: prompt received by the fake model for a non-raw user (values `shown`) has the rendered sentence masked, no trader or counterparty; raw author's prompt does contain them (as the asker may see them). Question is a quoted JSON string inside a per-request random-id UNTRUSTED block; a forged `<<<END UNTRUSTED QUESTION id=abc>>>` is neutralised (`‹‹‹ ›››`). Comments and notes never enter the prompt. No tools/functions in the request, key sent only as Bearer. 500-char limit holds; the console renders answers with `textContent`.
- Thread and note reads (`/threads`, `/notes`, `/comments/{id}/revisions`, `/me/inbox`, `/me/mentions`) mask the stored spans for every non-raw reader including compliance; quotes `{$.trader}` render `•••` for non-raw and values for raw; retract and hide remove the body from author, viewer and admin views, compliance and admin still see it in revisions.
- Inbox/notices carry no data; a revoked recipient sees `access:false` with `id:null`. Bridge payload (signed JSON) carries `•••` and quote paths, no values, no Authorization/secret. Compliance export zip (title, bodies, outbox) has no bridge URL, secret or API key.
- Snapshots: picture for recipients [viewer, author] is byte-identical to the picture for [viewer] on the whole view and on all nine panels (least privileged wins); title masked as `…`; `403 DRS-7015` for a recipient without the pack and for genomics (pack off). Picture fetch: sender, recipient, compliance only (other users `404`, no session `401`); after a pack revocation the recipient gets `403`.
- Cross-pack: directory scoped to shared packs (`qa-limited` does not list `qa-econ`; out-of-scope and nonexistent names both answer `422 unknown user`, no oracle); `@mention` of a user without the pack notifies nobody and the author is told only under `tell`; share to a user without the pack is skipped with a reason, not delivered; `admin` and `service` roles are not shareable.
- Export: create/get/download compliance-only (viewer, author, admin, console service `403`; no token `401`; personal API token of the compliance user cannot create exports or holds); the zip is deliberately unscrubbed and one-shot (second download `400`).
- Legal hold: entity, user, thread holds each give `423 DRS-7010` on `DELETE /admin/collab/threads/{tid}`, including a thread created after an entity hold and a thread another user only commented on (user hold); release then delete works; only compliance places or releases holds; admin cannot. Retention run as admin removes nothing held (`threadsHeld`). Retract and edit under hold keep the record. (Retention purge with a configured age was not run: keep-days is 0.)
- Hash chain: edits to share body, sender and masked_spans, and to revision body and actor, are all detected by `verify` (`ok:false`, id named).
- AuthZ: every collab, admin/collab, `/me/*`, `/threads*`, `/comments*`, `/shares*`, `/directory`, `/ask`, `/explain` endpoint is `401` without a token; garbage and re-signed tokens `401`; personal API tokens read only on all writes (shares, threads, comments, state, follow, inbox read, settings) and on admin writes, including for an admin token; IDOR on thread ids, comment ids, share ids, picture ids and inbox seqs (`PATCH/retract/state` on another user's comment `403`/`404`; another user's `seqs` change nothing; non-parties get `404 DRS-7001`, never `403`). Locked state is admin only.
- Console: anonymous `401`/redirect on every collab proxy; non-admin non-compliance `403` on all `/admin/collab/*`; compliance cannot reach bridges or retention, admin cannot reach holds, exports or verify. CSRF: evil `Origin`, `null` origin, evil `Referer` and `text/plain` bodies are refused `403`/`415` on share, ask, retract, inbox read, follow, hide, logout, account settings; same-origin JSON works.
- Email: subject and header injection by display name and note: no Bcc produced; user text in HTML is escaped, `${product}` and `${link}` in user text are not expanded; `<script>` is escaped.

Not exercised: panel-gated shares (no pack defines gates), legal-hold retention at a configured age, bridge redirect and non-allow-listed URL (needs a restart with different environment), email opt-outs, digest coalescing (`coalesce-window` set to 0).
