# QA-UX findings, 2026-10-03: the Build workbench (usability, accessibility, docs)

Severity is by user impact. **High 0 · Medium 8 · Low 18 · Info 3.** Every finding was reproduced; the script that shows it is named. Product code was not changed by the QA run; the fixes are marked on each row.
In one line: the workbench does what its guide says end to end (propose, approve, live; mouse and keyboard paths; shipping; CLI) and is fast, but its first impression is a false red "Problems 1", a few inspector fields cannot work, and error text/ phone layout/ quota rough edges remain.

## Medium

**UX-01 · Medium · A design of your own kind starts with a false "Problems 1: \"shipment\" is not a valid kind".** The YAML light check treats `match.kind` as an enum of the kinds the registry knows. Every design for a new kind (the guide's whole premise: "JSON files to a screen") and **7 of the 10 examples** (exposure, instrument, trade-ops, portfolio, counterparty-summary, risk-run, organisation) open with Problems 1 and the badge, while the server accepts and draws them. It stays on every later edit, hiding real problems in a list that is never empty. The 2026-10-03 CHANGELOG "examples open clean" fix covers only the two examples whose kind is a pack kind. Where: `console/web/static/js/studio-assist.js:148` (the "is not a valid <key>" branch for `match.kind`). Repro: `s1_new.py`, `s13_examples.py`, `s9_errors.py`. **Fixed** in b05bca8e (test_workbench_ux2_browser.py::test_a_design_of_your_own_kind_has_no_false_kind_problem).

**UX-02 · Medium · A mistyped expression gives no usable error on the canvas or in Problems.** Typing `rows: '$.legs[?'` in the YAML tab is accepted ("The YAML matches the design", revision up), then the canvas says **"Nothing to draw yet: the design needs a Sutra with panels and a sample"** (there are panels and samples), the status bar says "? not checked", the Problems tab is empty (except UX-01), and the only explanation is on the **Tests** tab: "The check could not run: 1 problem(s): [studio.sutra.yaml:6:5 DRS-2101 expression '$.legs[?': DRS-2101 the expression ends early ...] (DRS-2002)" (DRS-2101 twice, under a stale matrix). A wrong expression is the commonest authoring mistake; it should be a Problem with a line, and the canvas should say the check failed. Where: `console/web/static/js/build/canvas.js:100` (empty message), `build/problems.js` (no entry for a failed check), `build/tests.js`. Repro: `s10_yaml.py`, the 3-line script in LOG row 6. **Fixed** in b05bca8e (test_workbench_ux2_browser.py::test_a_mistyped_expression_is_a_located_problem_and_the_other_panels_are_drawn, test_partial.py).

**UX-03 · Medium · Some options of the 20 kinds cannot be set in the inspector, although a box is offered that always fails.** The guide (section 8) says a count is a number field. These are plain text boxes and refuse a number typed in them: `table.limit` ("must be a whole number of rows, 1 or more, not '5' (DRS-5023)"; 5 is a whole number), `table.expand`, `ladder.expand`, `pivot.expand` (a whole number or `all`: a number is sent as text). `graph.layout` (tree or force) is a text box, not a select. Not editable at all without the YAML tab: `histogram.markers` (a list of label/value/tone: a text box that always answers DRS-5023), the table/ladder `pivot` object (the form only has an on/off switch), the pivot `by` list (a value that is already a list shows "Set in the YAML tab"), tabs `body`. The other 15 options per kind checked are fine; every option has a labelled control (0 unlabeled controls in 20 kinds). Where: `console/web/static/js/build/inspector.js:75-87` (`control()`: typed only by `p.type`; `oneOf`/untyped options fall through to text), `LISTS` at line 27 lacks `markers`. Repro: `s5_kinds.py`, `s6_options.py`, `s25_numeric.py`. **Fixed** in 272d0572 (test_workbench_options_browser.py (every option of every kind has a labelled editor; numbers, selects, markers, pivot, by, body)).

(DRS-5001)", "DRS-5001 no Sutra (*.sutra.yaml) was found in the zip (DRS-5001)", "DRS-2003 nope@9 (DRS-2003)", "DRS-5005 you keep 50 designs ... (DRS-5005)"; the workbench status line too (`why()`), and the Tests tab ("DRS-2101 ... DRS-2101"). The server's detail already starts with the code; these write `detail + ' (' + code + ')'` instead of the shared helper. Where: `console/web/static/js/build-new.js:42`, `build-import.js:29`, `build-designs.js:28`, `build/ops.js:37`, `build/shared.js:30`; templates `build/design.html:29`, `designs.html:32`, `review.html:28`, `reviews.html:30`, `shared.html:28`; older `terminal/search.html:56`, `compare.html:33`. Repro: `s9_errors.py`, `s23_start.py`. **Fixed** in b05bca8e (test_workbench_ux2_browser.py::test_a_failed_request_says_its_code_once_on_every_build_page).

**UX-05 · Medium · Scratch designs eat the 50-design quota; at the limit the old addresses and Help links stop working, with no bulk clean-up.** Every visit of `/studio`, `/studio?example=`, an example's "Open as my copy" and every Help "Open as a copy" makes a design (kept 24 h). After about 50 clicks (my run reached it in 30 minutes) the answer to every one of them is a **413 page**: "DRS-5005 you keep 50 designs, the most allowed (drishti.builder.designs.max-per-user): delete one first (DRS-5005)" on the *My designs* page; the user must delete rows one by one (the table has no select-all/delete-unnamed). A failed *Create* also leaves a design behind ("The design was created: open it as it stands") that counts. Suggest: count only named designs, or evict the oldest scratch design, or offer "Delete all unnamed". Where: `console/routes/build_routes.py:181` (`/examples/{name}/open`), `studio_routes.py:55`, `build/designs.html`. Repro: `s8_redirects.py` x2, `s13_examples.py`, then `/studio?example=tree-table`. (Not in this wave: the governance/quota builder owns it.)

**UX-06 · Medium · A design's notes cannot be seen or edited anywhere in the workbench.** The guide promises an example opens with "its notes" and that "the design's notes travel in full" to the reviewer; nothing in the page shows them (no tab, field or Summary entry). For an example copy the notes are the example's README **including its raw HTML licence comment** (`<!-- Project Drishti ... -->`) that would go to a reviewer as-is. Where: `console/web/templates/build/design.html` (no notes control), `console/core/designs.py:48` (`"notes": ex.readme`). Repro: GET `/build/designs/{id}` of a tree-table copy: `notes` starts with the licence comment; `s13_examples.py` page text has no match. **Fixed** in 1ee0729f (test_workbench_ux2b_browser.py::test_the_notes_are_visible_editable_and_the_licence_comment_is_not_shown).

**UX-08 · Medium · At 390 px the page scrolls sideways on the YAML tab and on My designs (every theme).** YAML tab: page 681-683 px wide in a 390 viewport (the CodeMirror box is 666 px wide, 244 elements past the edge); My designs: 725-733 px (the 852 px table has no scroll wrapper). Design, Inspector, New and Review pages fit (390/390). Where: `console/web/static/css/build-workbench.css` (`.wb-pane` / CodeMirror width), `build/designs.html` table. Repro: `s15_themes.py` (7 themes x 2 widths), `s19_phone.py`. **Fixed** in 4ff7a824 (test_workbench_ux2b_browser.py::test_the_workbench_and_my_designs_do_not_scroll_sideways_on_a_phone).

**UX-10 · Medium · Keyboard-only: 71 Tab presses to reach the canvas, and no way back from the inspector.** From the Skip link: top bar, header buttons, 6 samples with their Remove buttons, 20 palette Add buttons, then the shape tree, then the canvas (71 stops). The skip link goes to `#main` (the whole page), there is no "skip to the screen". The guide's Enter on a panel moves focus into the inspector's first button; **Esc there does nothing** and focus is not returned to the panel, so the next key (e.g. N, B, Delete) is typed on a button (my script lost three steps to it; with a text field focused `b` was typed into the field). Also after N (add) focus goes to the new panel's first required input, so B right after types into it. Where: `console/web/templates/base.html:46` (skip link), `build/grid-keys.js`, `build/inspector.js`. Repro: `s3_kbd.py`. **Fixed** in 1ee0729f (test_workbench_ux2b_browser.py::test_a_skip_link_and_a_chord_reach_the_canvas_and_escape_leaves_the_inspector).

## Info

**UX-25 · Info · Performance is excellent.** Create to first canvas 0.2-0.35 s (6 and 50 samples); reload to first canvas 0.10-0.13 s (15 KB transferred, 0 external scripts); an inspector edit: operation answered in 15-25 ms, canvas redrawn from it, the check starts 0.82 s later (the debounce) and answers in 17-20 ms for **50 samples x 6 panels**; YAML typing to status 0.17 s; Tests tab 0.37 s (300 cells; the matrix is 6,224 px wide in a 382 px pane, scrolled inside). Heavier Sutras or real data were not measured. `s18_perf.py`, `s18b_perf.py`. **Addressed** in 4ff7a824 (no defect; test_workbench_ux2c_browser.py::test_a_check_of_many_samples_answers_quickly keeps a budget).

**UX-28 · Info · What is solid.** The guide followed literally works from New screen to a live view (`s7_e2e.py`: Submit for review -> "proposed P-000001" -> the author sees only Withdraw -> the approver sees the matrix and Approve -> My designs "live v1" -> workbench chip "live v1"); mouse and keyboard paths for drop, bind, suggestions, move, resize, delete, undo/redo, versions/diff/restore, tests matrix, sample switcher, preview with a file; viewers get a dimmed Save with an honest sentence; 409 between two tabs reloads with a clear message; file binding writes the file and takes an IDE edit back; export passes `sutra lint/test` and re-imports as a design; the share link works for another user and is dead after Revoke; ARIA: tabs with arrows/Home/End, a labelled `tree`, combobox+listbox on expression fields (`aria-activedescendant`), labelled dialogs, canvas panels named "Details, kv panel", 0 duplicate ids, no unlabeled control, visible focus rings in 7 themes; all 7 themes x desktop render without sideways scroll and without genuine AA contrast failures. **Addressed** in 4ff7a824 (no defect; what is solid stays covered by the end-to-end tests that already run).

**UX-29 · Info · Native `confirm()`/`prompt()` are used** for Auto-design over existing work, opening a .yaml and Bind to a file (a path typed in a browser prompt): not themable and awkward with some screen readers; the menus (role=dialog, non-modal) close on Tab out and do not trap focus, which is acceptable. **Fixed** in 4ff7a824 (test_workbench_ux2c_browser.py::test_the_workbench_asks_in_the_page_and_never_in_a_browser_dialog; test_ship_browser.py binds through the in-page dialog).
