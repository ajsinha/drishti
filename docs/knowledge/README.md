# Knowledge

*See what your data hasn't told you yet.* These pages say what the words of a bank's data mean, and how Drishti's data connects
them, so you can read a number and know where it comes from and what else it touches. Three primers, each a few domains, one part per
domain, written for a reader new to it, with real numbers from the demo data and the commands that show them. The primers explain in
plain words; the formulas live in the guides they link to.

## Each part has the same seven sections

1. **The idea in plain words**: what it is and why a bank cares.
2. **Glossary**: each term, one line, and the command that shows it.
3. **How the data connects**: the kinds, their links and their id conventions, from the packs' data contracts.
4. **A worked example on the demo data**: real numbers you can reproduce, with their business date.
5. **Questions to ask your data**: ready-made commands and what each reveals.
6. **Common confusions**: the mix-ups that cost people time.
7. **Where to go deeper**: the guides and tutorials.

## WHAT: ask from the command line

Type `WHAT` and press Enter to open this page. Type `WHAT` and a term to open its glossary entry: `WHAT PFE`, `WHAT netting set`,
`WHAT expected shortfall`. Case does not matter, and the term's long name and usual synonyms work too (`WHAT value at risk` opens
VaR). Words that are not a term open a search of these pages (`WHAT collateral posted`). On a data page, the **What does this mean?**
link beside the help **?** opens the part that explains it: the VaR explorer, `VRES` and `DESK` open Market risk; `CPTY`, `NSET`,
`CSA` and the exposure explorer open Counterparty credit risk (both in [Risk](risk.md)).

## For writers

The glossary is one data file, [glossary.yaml](glossary.yaml): a term, its long name, synonyms, its domain (a primer's part), a
one-line meaning and the command that shows it. `python3 tools/knowledge.py` writes every part's Glossary section and the A to Z above
from it; `python3 tools/knowledge.py --check` fails when a page differs, and the console's `WHAT` reads the same file, so the two never
drift. Add a term there, never in a page. Every command a primer names must work on the demo lake that `drishti.py lake demo` builds. A
formula already stated in a guide is linked, not repeated: the primer says it in words.
