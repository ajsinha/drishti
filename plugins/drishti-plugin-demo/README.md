# The demo connector

Plugin `demo` (`plugins/drishti-plugin-demo`: `DemoSourcePlugin`, `DemoTicker`, `DemoWalk`): the samples each enabled pack ships in
`config/packs/<pack>/samples/`, so a server with nothing installed shows working screens. It is the `default-route`, tried after a
kind's own route. **Switch it off in production** (`DRISHTI_DEMO_ENABLED=false`): it serves made-up data under real-looking names.

## What it reads

At start it reads, for each folder in `dirs` (filled by the packs, most general first), `catalog.json` and each kind's JSON Lines file,
once, into memory: the documents, each document's `walk` and a type-ahead index of every catalogue entry. It never reads the folders
again (an edited sample needs a restart). Reads are map lookups; type-ahead searches ids, titles and subtitles; reverse lookups scan
every document held at every depth for a value equal to the target id. Live samples move a little every `tick-ms` (400) while someone
watches them. It runs only **as itself** (`drishti.sources.plugins.demo`), never as a named connector, serves every kind, and is not
dated: every business date gets the same document.

## Data structure

The samples folder of a pack:

```
config/packs/<pack>/samples/
├── catalog.json      [{"kind": "bond", "id": "BND-BRVERD054608", "title": "BND-BRVERD054608", "subtitle": "Bond (security master) · …"}, …]
├── <kind>.jsonl      one document a line, in the catalogue's order (above about 50 MB: <kind>.part-001.jsonl, …)
└── …                 the older layout, <kind>/<id>.json, is still read
```

- **Id rule:** the catalogue entry's `kind` and `id`; only listed entries are loaded; a JSON Lines line is matched to its entry by
  position, else by its id value. An entry whose kind or id would leave the folder (`../`) is skipped.
- **Document:** the entity as its system of record holds it (UPPER_SNAKE, nested lists inside, e.g. a trade's `LEGS` → `CASH_FLOWS` →
  `RESETS`, `EVENTS`), plus a `_meta` block the connector removes and turns into provenance:

```json
{"VALUATION_ID": "TVAL-1000001", "TRADE_ID": 1000001, "COUNTERPARTY": "CP-HARBORPT", "MTM": 4121280, "PNL_1D": -277804, …,
 "_meta": {"source": "risk-engine", "generation": 1, "live": true,
           "walk": {"MTM": 9922, "derive": [{"set": "PNL_1D", "expr": "$.MTM - 4399084"}]}}}
```

| `_meta` key | Becomes |
|---|---|
| `source` | `provenance.source`: the name users see (`endur`, `risk-engine`, `md-hub`), not `demo` |
| `generation` | `provenance.generation`; each tick adds 1 |
| `live` | `provenance.live`; only live samples tick and can be subscribed to |
| `walk` | the fields that move on each tick (`{FIELD: step}`, coherent groups, `derive`, `append`); optional |

## Examples

```yaml
# drishti-server/src/main/resources/application.yaml (shipped)
drishti:
  sources:
    default-route: demo
    plugins:
      demo:
        enabled: ${DRISHTI_DEMO_ENABLED:true}

# application.local.yaml: freeze or slow the ticks
drishti:
  sources:
    plugins:
      demo:
        settings: { ticking: false, tick-ms: 1000 }
```

It has **no connector file**. Switch it off for one start with `DRISHTI_DEMO_ENABLED=false` (the *demo lakes* run configuration does);
a kind no other connector serves then answers `DRS-1002`. Each pack's generators under `tools/packgen/` write its samples.

## Troubleshooting

- `demo` missing from `/sources`, `failedToStart` names it: a `dirs` folder without `catalog.json`, or a sample that is not a JSON object.
- `demo` missing, no failure: it is off (`DRISHTI_DEMO_ENABLED=false`).
- A pack's samples are not served: the pack is not in `DRISHTI_PACKS`, or its `samples` folder does not exist.
- A live view does not tick: the sample's `_meta.live` is false (trades are not live; watch `trade-valuation`), `ticking: false`, or
  another live source holds the entity.
- Real ids answer with sample data, or an old picked date shows a sample: the demo is on beside the lakes; switch it off.
- Health is always `UP` while running; it reports no cache figures.
