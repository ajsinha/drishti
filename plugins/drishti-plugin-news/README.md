# The news connector

Plugin `news` (`plugins/drishti-plugin-news`): a connector that is code, not a store. It holds nothing; each document is computed
when it is asked for. **Privacy:** every time a name is not in the cache, the entity's name (and the edition) is sent to
`news.google.com`, so the connector is **off as shipped** and switching it on is the site's decision.

## What it reads

The id carries a name. For `NEWS-Federal_Reserve` the connector sends `GET <base-url>?q=<query>&hl=<language>&gl=<COUNTRY>&ceid=…`,
parses the RSS 2.0 answer (DOCTYPE and entities refused: no XXE), keeps items whose **title** names the entity or an alias
(`relevance: title`), applies the publisher allow and deny lists, sorts newest first, drops duplicates, and keeps `max-items`. The raw
answer is cached per name and edition for `cache-ttl-seconds`; concurrent reads of one name share one call. Nothing is listed ahead
of time: type-ahead offers only names asked for since the start. Undated, not live. In offline mode (`DRISHTI_OFFLINE=true`) it never
starts.

## Data structure

**Id rule:** `NEWS-<name>[@<language>-<COUNTRY>][~all]`: `id-prefix` (`NEWS-`), the name with underscores for spaces (at most 120
characters), an optional edition (`@ja-JP`) and `~all` to switch the relevance filter off for that read. Anything else is not held.

The document (kind `news`), from `GET /api/v1/entities/news/NEWS-Federal_Reserve/raw`, shortened:

```json
{ "NEWS_ID": "NEWS-Federal_Reserve", "ENTITY": "Federal Reserve", "ALIASES": ["Fed", "FOMC", "Powell"], "EDITION": "en-US",
  "RELEVANCE_FILTER": "on", "COUNT": 3, "FETCHED_AT": "2026-10-11 07:54 UTC", "FETCHED": 5,
  "ITEMS": [ { "PUBLISHED": "2026-10-09 18:45 UTC", "SOURCE": "Reuters", "TITLE": "Federal Reserve announces record quarter",
               "LINK": "https://news.example/a1", "SNIPPET": "" }, … ],
  "BY_SOURCE": [ { "SOURCE": "Reuters", "COUNT": 1 }, … ],
  "PIPELINE": [ { "STEP": "relevance", "KEPT": 4, "DROPPED": 1 }, { "STEP": "duplicates", "KEPT": 3, "DROPPED": 1 }, … ],
  "PROVENANCE": { "FEED": "Google News RSS (…)", "FETCHED": "…", "CACHED_FOR": "600 s", "TERMS": "Headlines and links belong to their publishers; …" } }
```

- `ITEMS[]`: one headline each; the title without Google's trailing ` - Publisher`, links http or https only, the snippet without
  tags and without a repeat of the title.
- `PIPELINE[]`: what each step kept and dropped, so a reader can see why a headline is missing (`sources` appears when a list is set).
- Provenance: `live: false`, `businessDate: null`. A name nothing is written about is a valid document with `COUNT: 0`.

## Examples

```yaml
# config/connectors/news.yaml (written from the news-and-markets pack's template, enabled: ${DRISHTI_NEWS_ENABLED:false})
plugin: news
enabled: true
kinds: [news]
settings:
  relevance: title
  max-items: '15'
  cache-ttl-seconds: '600'
  deny-sources: Some Spam Site
  aliases.Federal_Reserve: Fed, FOMC
```

A pack reads it from an entity's document: `"NEWS_ID": "NEWS-Federal_Reserve"` and a panel `source: "link($.NEWS_ID, 'news')"`, `rows:
$.ITEMS`. An annotated copy is `config/connectors.examples/other/news.yaml`. There is no loader.

## Troubleshooting

- `DOWN: <reason> (tried again on the next request)`: the last call failed; health returns to `UP` at the next success. Connection
  failures, timeouts, 429 and 5xx are retried `retries` times; an older cached answer is served if one is held.
- `the response is not a readable RSS feed`: an HTML error page or broken XML (a proxy, a changed endpoint).
- News panels show *pending* on the first view: the call is slower than `drishti.graph.link-budget` (40 ms); the next view shows them.
  A site using this pack sets the budget to a second or two.
- A bad setting fails the start with the setting's name.
