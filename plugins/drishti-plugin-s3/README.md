# The s3 connector

Plugin `s3` (`plugins/drishti-plugin-s3`): the `file` connector's file-per-entity layout, in a bucket. For documents another system
already writes to object storage (stress results, reports, model outputs), a few thousand to a few tens of thousands of objects. For
a book of millions a day in object storage use `delta` or `iceberg` on S3 instead.

## What it reads

Every `.json` object under `bucket`/`prefix`, listed at start and every `rescan-seconds`: the listing gives the date folders, kinds and
ids (type-ahead, from memory). Opening an entity is one `GET` per date folder tried, cached for `cache-seconds` (misses too). It is
dated: a date's folder answers, else the newest older folder within `lookback-days`, else the undated object. Searches read documents
one `GET` each (no promoted columns); there are no reverse lookups, no live push and no *known at*. It only reads. Always give the
connector `kinds:`: an empty listing otherwise makes it a candidate for every kind.

Defaults as `S3SourcePlugin.start` reads them: `region` `us-east-1`, `path-style` `true` (read only with `endpoint`), `rescan-seconds`
`60`, `cache-seconds` `30` (a read or a miss), `cache-entries` `10000`, `lookback-days` `10` (calendar days back from the date asked);
blank `access-key` means the AWS default credential chain; `source-name` is `s3` for the plugin as itself. Timeouts are fixed in the
code: 5 s connect, 20 s socket.

## Data structure

```
s3://risk-docs/eod/                             bucket and prefix
  stress-result/STR-CLIMATE-2026Q3.json         <kind>/<id>.json: undated, serves every date
  2026-09-30/stress-result/STR-GFC2008-RATES.json   <yyyy-MM-dd>/<kind>/<id>.json: for that business date
```

- **Id rule:** the kind is the folder name, the id the object name without `.json`, both case-sensitive; an id cannot contain `/`.
- **Ignored:** keys not ending in `.json` (`.json.gz` too), keys with more levels, three levels whose first is not a real date, keys
  outside the prefix.
- **Document:** the whole object, one JSON document, handed over unchanged; nothing in it is required. Provenance: `generation` is the
  object's `Last-Modified` (epoch milliseconds), `businessDate` the date folder (null for an undated object).

## Examples

```yaml
# config/connectors/risk-docs.yaml
plugin: s3
kinds: [stress-result]
settings:
  bucket: ${RISK_DOCS_BUCKET:risk-docs}
  prefix: eod/
  region: us-east-1
  # endpoint: https://minio.bank.example       # an S3-compatible store
  # access-key: ${S3_ACCESS_KEY}
  # secret-key: ${S3_SECRET_KEY}
```

On AWS leave out `endpoint` and the keys, set `region` to the bucket's region and give the server an instance role. Write objects
with any tool (`aws s3 cp`), into `<prefix><yyyy-MM-dd>/<kind>/<id>.json`; a lifecycle rule keeps the prefix small.

## Troubleshooting

- `failedToStart`: `s3 plugin needs settings.bucket`: set `bucket`.
- `DOWN: SdkClientException: Unable to execute HTTP request: … (retrying)`: the endpoint is unreachable (DNS, firewall, proxy).
- `DOWN: S3Exception: Access Denied (… Status Code: 403 …) (retrying)`: credentials or bucket policy; check `s3:ListBucket` and
  `s3:GetObject`.
- `DOWN: NoSuchBucketException: … (retrying)`: a wrong `bucket` or `endpoint`. `… Status Code: 301 …`: set `region`.
- A new object is not found: its miss is cached (`cache-seconds`), or the next rescan has not run.
- A picked date shows an older `businessDate`: that date's folder lacks the entity; an older folder within `lookback-days` answers.

Every health text is in the full document, section *Diagnosing*.
