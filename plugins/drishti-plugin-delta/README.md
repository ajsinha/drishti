# The delta connector

Plugin `delta` (`plugins/drishti-plugin-delta`): a million trades a day kept for seven years, with type-ahead in tens of
milliseconds and searches over a whole day from its promoted columns. It never loads a day: each question reads only the files,
row groups and columns it needs.

## What it reads

A lake root (`./data/delta` or `s3://bucket/prefix`) holds a folder per data domain (`domain`), and under it one Delta table per kind
(or per `table.<kind>` when several connectors serve one kind, such as the trading pack's `trade_endur`, `trade_calypso` and
`trade_murex`, joined by `union: true`). The tables are listed at start and at every re-index, so a table added while the server
runs is found without a restart. Two engines: `native` (the default; `java.nio` and the AWS SDK, no Hadoop) and `hadoop` (also
`abfs://` and `gs://`). It only reads: whatever writes the lake must follow the layout below.

## Data structure

```
<root>/trading/trade/                       one Delta table per kind (or table.<kind>)
  _delta_log/                               the transaction log
  business_date=2026-09-30/part-0000N-….snappy.parquet   a partition per business day; files of 250,000 rows sorted by id
```

| Column | Type | Content |
|---|---|---|
| `id` | string | the entity id (`MX-20000001`); `id-column` renames it |
| `doc` | string | the whole JSON document, exactly what a view shows; `doc-column` renames it |
| `business_date` | date | the partition column; `date-column` renames it |
| promoted fields (`TRADE_ID`, `PORTFOLIO`, …) | string or double | copies of `layout.<kind>.columns`; `LEGS.CURRENCY` is the column `LEGS__CURRENCY` |

- **Id rule:** `id`, unique per business day; rows sorted by id within a day (`layout.<kind>.sort-by: id`), so the per-file and
  per-row-group minimum and maximum let a reader skip everything but one row group.
- **Shape:** row groups of `layout.<kind>.row-group-rows` (the trading pack: 1,000), files of `file-rows` (250,000); writers set
  `delta.dataSkippingStatsColumns` to `id`, `business_date` and the promoted columns, so the log stays small.
- **Modes:** `mode.<kind>: snapshot` (every entity every day) or `effective` (a row when an entity changes).
- **Nested data** stays inside `doc` (for `trade`: `LEGS[]`, `EVENTS[]`).

## Examples

```yaml
# config/connectors/trade-endur.yaml
plugin: delta
kinds: [trade]
settings:
  root: ${DRISHTI_DELTA_ROOT:${drishti.data.dir:./data}/delta}
  domain: trading
  table.trade: trade_endur          # <root>/trading/trade_endur
  union: "true"                     # one of the source systems that together are the kind
  layout.trade.columns: TRADE_ID,SOURCE_SYSTEM,PRODUCT_TYPE,CURRENCY,QUANTITY,COUNTERPARTY,PORTFOLIO
  layout.trade.row-group-rows: '1000'
```

On S3-compatible storage add `root: s3://lake-prod/delta`, `s3.endpoint`, `s3.region`, `s3.access-key: ${LAKE_ACCESS_KEY}` and
`s3.secret-key: ${LAKE_SECRET_KEY}` (`config/connectors.examples/other/customer-lake.yaml`). Build a demo lake with
`tools/load-delta.sh` (`--trades 50000` for a generated book) or `tools\windows\load-delta.ps1`.

## Troubleshooting

- `DOWN: cannot reach <root>/<domain>`: the folder or bucket is not reachable (credentials, region or endpoint for S3).
- `DOWN: no Delta tables under <root>/<domain>`: reachable, but nothing with a `_delta_log`; build the lake or fix `root`/`domain`.
- `UP (engine: native; not laid out as the pack declares: trade (12 of 16 columns); searches read documents)`: the writer did not
  write the promoted columns; `maintain.py relayout --root … --domain …`.
- `DEGRADED: cannot read trade 2026-09-30: …`: a file in a codec the engine does not decompress (BROTLI, LZO), a damaged or missing
  Parquet file, or a log missing a commit; the reason says which.
- `domain escapes the Delta root` under `failedToStart`: `domain` contains `..` or starts with `/`.
- `DRS-1004 timed out` on a single read: very large row groups or distant storage; rewrite with smaller row groups.

Every health text is in the full document, section *Diagnosing*.
