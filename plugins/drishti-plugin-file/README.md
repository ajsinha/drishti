# The file connector

Plugin `file` (`plugins/drishti-plugin-file`): the simplest store Drishti reads. No database, no cluster, no service to run: each
business day of a kind is one file of JSON lines, which any tool can write and anyone can open in an editor. Right for a demo, a
nightly export or reference data kept by hand; for a million entities a day kept for years use Delta Lake or PostgreSQL.

## What it reads

`<root>/<domain>/<yyyy-MM-dd>/<kind>.jsonl` files (and undated `<root>/<domain>/<kind>.jsonl`, the same for every date), listed every
`rescan-seconds` (30). The first read of a day indexes it (ids, line offsets and promoted fields); the newest day is indexed in the
background, older days on first use, and a changed file is re-indexed when next read. Kinds are `snapshot` or `effective`
(`mode.<kind>`). It also reads the older layout of one file per entity (`<root>/<kind>/<id>.json` or `.csv`, CSV deprecated: logged once per file and named in health, dated
`<root>/<yyyy-MM-dd>/<kind>/<id>.json`), as the public-data feeds use. No time travel: a *known at* read is refused with `DRS-1007`.
It never writes; `tools/load-files.sh` (`JsonlLoader`) does.

## Data structure

```
<root>/trading/2026-09-30/trade.jsonl         every trade of 30 September, one per line, any order
<root>/reference/2026-09-30/counterparty.jsonl
<root>/reference/desk.jsonl                   undated: serves every date
```

A line is one JSON object, in either form (a file may mix them):

```json
{"domain": "trading", "kind": "trade", "id": "MX-20000001", "date": "2026-09-17",
 "doc": "{\"SOURCE_SYSTEM\": \"MUREX\", \"TRADE_ID\": \"MX-20000001\", …}",
 "columns": {"TRADE_ID": "MX-20000001", "QUANTITY": 242000000.0, "PORTFOLIO": "BOOK-RATES-3"}}
{"BOOK_ID": "BOOK-RATES-3", "NAME": "Rates book 3", "DESK": "DESK-RATES", "CURRENCY": "USD"}
```

- **The loaders' row:** `doc` is the document (a JSON string or an object); `columns` carries the promoted fields
  (`layout.<kind>.columns`) so they are indexed without reading the document; without `columns` they are read from `doc`.
- **A plain document:** the id is the field named by `id-field` (`id` by default; `BOOK_ID` above).
- **Id rule:** one entity per id per day; when an id repeats, its last line is the entity (counted as `duplicateIds`).
- **Values:** `NaN` and `Infinity` are read as no value; a promoted field of mixed types keeps each value as the document holds it.
- **Unreadable lines** (truncated, not an object, no id, beyond `max-document-mb` or `max-nesting-depth`) are skipped and counted; the
  rest of the day is served.

## Examples

```yaml
# config/connectors/trading-store.yaml
plugin: file
kinds: [trade]
settings:
  root: ${DRISHTI_FILES_ROOT:${drishti.data.dir:./data}/files}
  domain: trading                     # reads <root>/trading
  layout.trade.columns: TRADE_ID,SOURCE_SYSTEM,PRODUCT_TYPE,CURRENCY,QUANTITY,COUNTERPARTY,PORTFOLIO
```

Ready-made files for the six banking domains: `config/connectors.examples/files/`. Load the samples with `tools/load-files.sh` (add
`--trades 10000` for a generated book). Writing files yourself needs no loader: write `<kind>.jsonl.tmp` and rename it into place.

## Troubleshooting

- `DOWN: no directory …`: the root (or `<root>/<domain>`) does not exist; create it, or fix `root`/`DRISHTI_FILES_ROOT`.
- `UP (1 unreadable line in trading/2026-09-30/trade.jsonl (line 201: …))`: fix or rewrite those lines; searches over that day say
  `partial: true` with the reason.
- `… duplicate ids in …, the last line of each kept (…)`: write each id once.
- A new file is not served: the next rescan has not run (`rescan-seconds`).
- A kind is missing from type-ahead: its lines have no id field; set `id-field` for plain documents.
- A view fails with `DRS-1003 <connector> failed reading …`: the day's file is there but cannot be opened (permissions).

Every health text is in the full document, section *Diagnosing*.
