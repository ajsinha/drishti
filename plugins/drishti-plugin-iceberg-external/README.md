# The iceberg-external connector

Plugin `iceberg-external` (`plugins/drishti-plugin-iceberg-external`): Iceberg tables as their owners wrote them, read through
drishti-iceberg. A table is a kind, a row is a document, every primitive column is searchable without a pack declaring it. For
tables Drishti's own loader writes use `iceberg`, which reads that layout faster.

## What it reads

Tables reached the way the `iceberg` connector reaches them: path-based under `root` (local disk or `s3://`), a REST catalog
(`catalog: rest`: Apache Polaris, Snowflake Open Catalog, Glue's Iceberg endpoint, Unity Catalog, Nessie, Lakekeeper, Gravitino), or
one metadata file (`metadata-location.<kind>`). Each kind is configured under `tables.<kind>`, or `tables: auto` serves every table of
`namespace`. It applies merge-on-read position and equality deletes, reads *known at* from the snapshot log with that snapshot's
schema, and **never writes**: maintenance is the owners'. Format version 3, encrypted tables, ORC and Avro data files are refused by
name; tables in Azure, Google Cloud Storage or HDFS are not read; branches and tags other than `main` are not read.

## Data structure

Depends on the source; mapping via `tables.<kind>.*`:

| Iceberg type | In the document |
|---|---|
| boolean, int, long, float, double | JSON boolean and number |
| decimal(P,S) | a number; `decimals: string` keeps full precision as text |
| date, time, timestamp, timestamptz | ISO-8601 text (`2026-09-30`, `2026-09-30T18:30:00Z`) |
| string, uuid | text |
| fixed, binary | Base64 text (or left out with `binary: omit`) |
| struct / list / map | an object / an array / an object when keys are text, else an array of `{key, value}` |

- **Document:** the whole row (`document: row`, the default) or one JSON column (`document: column:<name>`). Column names keep their
  case; `columns.rename` and `columns.exclude` adjust them. Columns are matched by field id, so a renamed column keeps its values.
- **Id rule:** `tables.<kind>.id`, one column or several joined by `id-separator` (`:`, giving `MUREX:T-007`); by default the table's
  identifier fields. A table with neither is not served.
- **Business date:** `date` (a date column, or a timestamp with `date-from: day` in `date-zone`, UTC by default); by default the
  partition spec's date; with neither the kind is current only.
- **Mode:** `snapshot` (every entity every day) or `effective` (a row when the entity changes). `links.<column>: <kind>` names
  columns that hold other kinds' ids, for reverse lookups. Nested struct fields are searchable to `depth` (2).
- **One entity:** a table sorted or bucketed by its id is read in one row group; an unsorted table builds an id index per day once
  (about 60 B an id, `id-index-mb`).

## Examples

```yaml
# config/connectors/risk-mart.yaml: tables a Spark pipeline writes to a Polaris catalog
plugin: iceberg-external
kinds: [trade, counterparty]
settings:
  catalog: rest
  uri: https://polaris.example.com/api/catalog
  warehouse: risk
  credential: ${POLARIS_CLIENT_ID}:${POLARIS_CLIENT_SECRET}
  tables:
    trade:
      table: risk_mart.trades                       # namespace.table
      id: [SOURCE_SYSTEM, TRADE_ID]                 # MUREX:20000017
      date: BUSINESS_DATE
      columns: { exclude: [ETL_LOAD_TS, _FILE], rename: { cpty_id: COUNTERPARTY } }
      links: { COUNTERPARTY: counterparty }
    counterparty:
      table: refdata.counterparties
      id: CPTY_ID                                   # no date: current only
```

A ready-made file is `config/connectors.examples/other/iceberg-external-risk-mart.yaml`. `tables: auto` with `namespace: risk_mart`
serves every table of the namespace (`TRADE_EVENTS` becomes the kind `trade-events`). `StarterSchemas` and `tools/drishti.py pack make`
draft a pack from the tables' schemas (the full document, section 9).

## Troubleshooting

- `DEGRADED: trade: no table risk_mart.trades: looked in <root>/risk_mart/trades/metadata for version-hint.text, v<N>.metadata.json and
  a catalog's NNNNN-<uuid>.metadata.json (the folder is empty)`: the table is not where `table` says; fix `root` or `tables.<kind>.table`.
- `… no id: the table has no identifier fields; set tables.<kind>.id`: name the id columns.
- Any configured table not served makes the connector `DEGRADED`; the tables it does serve answer as usual.
- First lookup of a day slow: the table is unsorted and its id index is being built; Health suggests sorting it past
  `id-index-warn-rows`.
- Type-ahead `partial` on a table with no date: it passed `max-index-rows`.
