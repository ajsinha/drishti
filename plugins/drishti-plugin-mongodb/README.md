# The mongodb connector

Plugin `mongodb` (`plugins/drishti-plugin-mongodb`): a document per entity per day, read as columns. One entity is one `_id` lookup;
a day's promoted fields come from a narrow second collection, so a search over a million trades does not decompress a million
documents. `tools/load-mongodb.sh` (or any writer keeping the same layout) fills it.

## What it reads

A data domain (`trading`) is two collections in the database (`drishti` by default): `<collection>` with the documents and
`<collection>_columns` with only the promoted fields. The kinds and their days come from a distinct scan of the `day_ids` index, the
day's ids from a covered query, both re-read every `refresh-seconds`. Retention is deleting old days (`--keep-days`) or a TTL
(`--ttl-days`, an `expireAt` field). Read preference is configurable for replica sets. It is read-only. Tested on MongoDB 7.0
(8.0 refuses to start on Linux 6.19 and newer, SERVER-121912).

## Data structure

| Collection | Document | `_id` | Fields |
|---|---|---|---|
| `trading` | one per entity per business day | `trade/MX-20000017/20260930` | `kind`, `id`, `date` (yyyyMMdd as a number), `doc`, `c` (the promoted fields) |
| `trading_columns` | the same keys, only for entities with promoted fields | `trade/MX-20000017/20260930` | `kind`, `id`, `date`, `c` |

```
{ _id: 'trade/CLY-3000157/20260917', kind: 'trade', id: 'CLY-3000157', date: 20260917,
  doc: '{"SOURCE_SYSTEM":"CALYPSO",…}',                         the JSON document, as text (or BSON with --doc-format bson)
  c: { TRADE_ID: 'CLY-3000157', PRODUCT_TYPE: 'GOVT_BOND', QUANTITY: 17179094, PORTFOLIO: 'BOOK-FI-3', … } }
```

- **Indexes:** `_id_` (a snapshot read is the exact key; an effective read the last key of the range `kind/id/` … `kind/id/yyyyMMdd`)
  and `day_ids` `{kind: 1, date: 1, id: 1}` on both collections. Nothing else is needed.
- **Id rule:** the key is `<kind>/<id>/<yyyyMMdd>`; a read also checks the `id` field, so an id containing `/` is never confused.
- **Promoted fields** sit under `c`; numbers are doubles, the rest text; a nested path `LEGS.CURRENCY` is `LEGS__CURRENCY`.
- **Document:** `doc` holds the JSON document as text by default (about twice as fast to read as embedded BSON); nested lists stay
  inside it. The loader creates collections with zstd block compression.

## Examples

```yaml
# config/connectors/trade-endur.yaml
plugin: mongodb
kinds: [trade]
settings:
  domain: trading                     # the collections trading and trading_columns
  uri: ${DRISHTI_MONGODB_URI:mongodb://localhost:27017}
  database: ${DRISHTI_MONGODB_DATABASE:drishti}
  layout.trade.columns: TRADE_ID,SOURCE_SYSTEM,PRODUCT_TYPE,CURRENCY,QUANTITY,COUNTERPARTY,PORTFOLIO
```

Ready-made files for the six banking domains: `config/connectors.examples/mongodb/`; over TLS: `other/positions-mongo.yaml`. Load data
with `tools/load-mongodb.sh mongodb://localhost:27017 drishti` (add `--trades N --days D`, `--keep-days N` or `--ttl-days N`).

## Troubleshooting

- `DOWN: cannot reach MongoDB (…)`: wrong `uri`, credentials, or the server is down; the driver reconnects by itself.
- `DOWN: no documents in drishti.trading`: nothing loaded, or the wrong `database`/`collection`/`domain`.
- `UP (not laid out: missing index day_ids …)`: written by another tool;
  `db.trading.createIndex({kind: 1, date: 1, id: 1}, {name: "day_ids"})`, on `trading_columns` too.
- `UP (no trading_columns collection: …)`: the writer does not write the narrow copy; reload with the loader.
- `tls.* is set but TLS is not switched on: set tls.enabled: true (or put tls=true in the uri)`: switch TLS on.
- `DOWN: cannot reach MongoDB (Exception authenticating)` with x.509: the certificate's subject is not a user in `$external`.

Every health text is in the full document, section *Diagnosing*.
