# The activemq connector

Plugin `activemq` (`plugins/drishti-plugin-activemq`, on the shared `MessageStateSource` of `drishti-messaging`): entity changes
published to ActiveMQ Classic, kept on local disk, with views that tick on every message.

## What it reads

`destinations` lists queues and topics (`queue:<name>`, `topic:<name>`, or a bare name, a queue). One session in `CLIENT_ACKNOWLEDGE`
mode consumes them; a topic gets a durable subscription named `drishti-<source-name>-<topic>` under the client id (default
`drishti-<source-name>`). A queue delivers each message once and keeps no history, so the connector writes each message to its **state
store** (RocksDB under `<state.root>/<connector name>`), the memory cache and type-ahead, pushes it to open views, and only then
acknowledges it. Reads never touch the broker. The store is the **only copy** of what the queue delivered: treat it as data. Undated,
no reverse lookups; the client speaks OpenWire only (not Artemis AMQP).

## Data structure

A message is a `TextMessage` (or a `BytesMessage` read as UTF-8) whose body is JSON. Two optional string properties are read: `id`
(the entity id) and `deleted` (`true` deletes). Other headers and properties are ignored.

- **A destination with a kind** (`kind.<destination>`, or `kind`; the name without `queue:`/`topic:`): the body is the document.
  **Id rule:** the `id` property, else the body's top-level field `id-field.<destination>` (else `id-field`, default `id`).

  ```text
  destination: queue://limits     (kind.limits: credit-limit, id-field.limits: LIMIT_ID)
  body: {"LIMIT_ID": "LIM-ALDERSHOT", "COUNTERPARTY": "CP-ALDERSHOT", "CURRENCY": "USD", "LIMIT": 338000000.0, "USED": 241900000, …}
  ```

- **Without a kind**, the body is an envelope; one destination can carry several kinds:
  `{"kind": "netting-set", "id": "NS-MERIDIAN-RE-ISDA", "doc": {"NETTING_SET_ID": "NS-MERIDIAN-RE-ISDA", "NET_MTM": 18450210.55, …}}`.
- **Deletes:** property `deleted=true`; an envelope with `"doc": null` or no `doc`; an empty body with an `id` property on a destination
  with a kind. Pushed to open views (greyed, with when it was deleted).
- **Rejected** (counted, acknowledged, dropped; no dead-lettering): a body that is not JSON, no kind, no id.
- **Stored:** compact JSON under the key `<kind>/<id>`; provenance `source` = source-name, `generation` a counter per run,
  `fetchedAt` when received (or first read back after a restart), `live: true`, no business date.

## Examples

```yaml
# config/connectors/limits-mq.yaml
plugin: activemq
enabled: ${DRISHTI_LIMITS_MQ:false}
kinds: [credit-limit, netting-set]
settings:
  broker-url: ${AMQ_URL:failover:(tcp://localhost:61616)}
  user: ${AMQ_USER:}
  password: ${AMQ_PASSWORD}
  destinations: queue:limits,topic:limit-breaches,queue:risk.entities
  kind.limits: credit-limit
  id-field.limits: LIMIT_ID
  client-id: ${AMQ_CLIENT_ID:drishti-limits-mq}     # unique per server
  state.max-gb: '20'
  stale-after: 15m
```

Ready-made files in `config/connectors.examples/other/`: `activemq-ssl.yaml` (`ssl://`, private CA) and `ops-events.yaml` (user and
password from the environment, PKCS12 truststore). There is no loader: producers publish messages.

## Troubleshooting

- `DOWN: connecting to failover:(…)` for minutes: the broker is unreachable (address, firewall, TLS); it connects by itself once reachable.
- `DOWN: InvalidClientIDException: … (reconnecting)`: another server uses the same `client-id`; give each its own.
- `DOWN: JMSSecurityException: … (reconnecting)`: wrong `user`/`password` or no permission on a destination.
- `DOWN: … (messages are not acknowledged and come again)`: the state store cannot write (disk full, I/O error); free disk on `state.root`.
- `rejected` grows: `kind.<destination>` and `id-field.<destination>` do not match the bodies.
- Entities split between two servers: both read the same queue; use a topic, or a queue per server.
- A removed topic's durable subscription keeps collecting on the broker: remove it there.

Every health text is in the full document, sections *Failure and recovery* and *Diagnosing*.
