# The cassandra connector

Plugin `cassandra` (`plugins/drishti-plugin-cassandra`): one entity in a few milliseconds, type-ahead from memory and searches over a
day's promoted columns, from a keyspace that `tools/load-cassandra.sh` (or any writer keeping the same layout) fills.

## What it reads

A data domain (`trading`) is a **keyspace**; each kind is one table, one row per entity per business day, the whole JSON document in
`doc` plus the promoted fields as narrow columns. The kinds are learnt from the schema (each table's comment `drishti kind: <kind>`),
never by scanning. It reads Apache Cassandra 4.0–5.0, ScyllaDB and DataStax Astra; Amazon Keyspaces is wired but not yet checked. It is
read-only: its role needs `SELECT` on the keyspace.

## Data structure

The expected layout (the loader writes it with `--create`):

```sql
CREATE TABLE "trading"."trade" (                         -- one table per kind; netting-set becomes netting_set
    "business_date" date, "generation" int, "bucket" smallint, "id" text,
    "doc" text,                                          -- the whole JSON document, exactly what a view shows
    "trade_id" text, "portfolio" text, "quantity" double, "legs__currency" text,   -- promoted fields (layout.<kind>.columns)
    PRIMARY KEY (("business_date", "generation", "bucket"), "id")
) WITH comment = 'drishti kind: trade';

CREATE TABLE "trading"."entity_days" ("kind" text, "id" text, "business_date" date,
    PRIMARY KEY (("kind", "id"), "business_date")) WITH CLUSTERING ORDER BY ("business_date" DESC);

CREATE TABLE "trading"."kind_days" ("kind" text, "business_date" date, "generation" int, "buckets" int, "rows" bigint,
    "loaded_at" timestamp, PRIMARY KEY ("kind", "business_date")) WITH CLUSTERING ORDER BY ("business_date" DESC);
```

- **Id rule:** the `id` clustering column is the entity id; the bucket is `murmur3(id) mod buckets` (Murmur3 x86 32-bit, seed 0, UTF-8).
- **Document:** `doc` holds the JSON document as the pack's kind defines it (for `trade`: `LEGS[].CASH_FLOWS[].RESETS[]`, `EVENTS[]`,
  see the trading pack's README); nested lists stay inside the document.
- **Promoted columns:** a path `LEGS.CURRENCY` is the column `legs__currency` (lower case, other characters `_`; numbers `double`,
  everything else `text`).
- **Generations:** a day appears whole or not at all; readers follow `kind_days`, which names the generation to read.

## Examples

```yaml
# config/connectors/trade-endur.yaml
plugin: cassandra
kinds: [trade]
settings:
  domain: trading                                   # the keyspace
  contact-points: ${DRISHTI_CASSANDRA_CONTACT_POINTS:localhost:9042}
  local-datacenter: ${DRISHTI_CASSANDRA_DATACENTER:datacenter1}
  username: ${DRISHTI_CASSANDRA_USERNAME:}
  password: ${DRISHTI_CASSANDRA_PASSWORD:}
  layout.trade.columns: TRADE_ID,SOURCE_SYSTEM,PRODUCT_TYPE,PORTFOLIO,COUNTERPARTY,CURRENCY,QUANTITY
```

Ready-made files: `config/connectors.examples/cassandra/` (the six banking domains), `other/cassandra-tls.yaml` (mutual TLS) and
`other/cassandra-astra.yaml` (Astra). Load data with `tools/load-cassandra.sh localhost:9042 datacenter1 --create --create-keyspace 1`.

## Troubleshooting

- `DOWN: … no connection to <host:port>`: wrong `contact-points`, a closed port or the node down (`nc -z <host> 9042`).
- `DOWN: keyspace … does not exist` / `has no kind_days table`: set `keyspace`, or load with `--create`.
- `… TLS to <host:port> failed …`: the message names the fix (`tls.ca-file`, a client certificate, `tls.verify-hostname`).
- A new day does not appear: the catalogue is re-read every `refresh-seconds`; Admin → Caches → purge.
- Searches say `partial: true`: the field is not a promoted column; add it to `layout.<kind>.columns` and reload.

Every health text is in the full document, section *Diagnosing*.
