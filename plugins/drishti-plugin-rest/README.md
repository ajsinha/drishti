# The rest connector

Plugin `rest` (`plugins/drishti-plugin-rest`): reads an entity from a service that already has a per-entity JSON API, copying
nothing. Every view is one request to the service.

## What it reads

For a read of `<kind>/<id>` it sends `GET <base-url><path>` with `{kind}` and `{id}` replaced by the URL-encoded kind and id
(`URLEncoder`, `+` turned into `%20`, so `/` becomes `%2F`), with `Accept: application/json` and every `header.<Name>` setting. One
JDK `HttpClient` per connector, connections kept alive; `timeout-ms` is both the connect and the request timeout; redirects are not
followed. Its manifest is `SourceCapabilities.FETCH_ONLY`: no search, no type-ahead, no reverse lookups, no live updates, not dated.
Every other question about its kinds must be answered by another connector.

| Setting | Type | Default | Meaning |
|---|---|---|---|
| `base-url` | string |  | **Required.** The service root; trailing `/` are removed. Empty: the connector fails to start |
| `path` | string | `/{kind}/{id}` | Appended to `base-url`; `{kind}` and `{id}` are replaced by the URL-encoded kind and id |
| `kinds` | list |  | Comma list of kinds served; a connector's own `kinds:` list takes precedence |
| `generation-header` | string | `ETag` | Response header holding a numeric version (quotes removed); otherwise the fetch time in milliseconds |
| `timeout-ms` | int | `2000` | Connect timeout and request timeout, in milliseconds |
| `header.*` | string |  | A request header: header.<Name> (header.Authorization: Bearer ${SERVICE_TOKEN}) |

Every connector also takes `source-name`, `mode.*`, `domain`, `stale-after`, `union` (docs/connectors/CONNECTOR_FILES.md). It takes the shared `tls.*` settings (docs/connectors/TLS.md). It takes the shared `proxy.*` settings for an outbound HTTP proxy (CONNECTOR_DEVELOPER_GUIDE.md).

## Data structure

The service's answer decides everything:

| Answer | Becomes |
|---|---|
| `404` | not held here: the next connector for the kind is asked |
| any other status of 400 or more | a failure (`<source-name> answered HTTP <status> for <kind>/<id>`, `DRS-1003`); not passed on |
| below 400 (`200`, `204`, `3xx`) | the body parsed as JSON is the document; an empty body is an empty document, *found* |

- **Document:** the body exactly (any JSON value; services return an object), nested structures as the service sends them.
- **Id rule:** the entity id is what the user asked for; the service maps it. `path` may move it into the query string
  (`/lookup?type={kind}&key={id}`) for ids holding `/`.
- **Generation:** the response header `generation-header` (default `ETag`) with every `"` removed, if only digits remain (`ETag: "77"` →
  77; a weak `W/"77"` is not); otherwise the fetch time in milliseconds.
- **Provenance:** `live: false`, `businessDate: null`: the document is the service's current answer.

```http
GET /api/counterparty/CP-HARBOURVIEW HTTP/1.1
Accept: application/json
Authorization: Bearer eyJ…

HTTP/1.1 200 OK
X-Version: 42

{"COUNTERPARTY_ID": "CP-HARBOURVIEW", "NAME": "Harbourview Capital LLP", "RATING": "A", "NETTING_SETS": ["NS-HARBOURVIEW-ISDA"], …}
```

## Examples

```yaml
# config/connectors/pricing-api.yaml
plugin: rest
kinds: [price]
description: Prices from the pricing service
settings:
  base-url: https://pricing.example.com/api
  path: /{kind}/{id}
  timeout-ms: '1500'
  generation-header: X-Version
  header.Authorization: Bearer ${PRICING_TOKEN}
# the pack (or application.yaml) routes the kind:  routes: { price: pricing-api }
```

Ready-made files in `config/connectors.examples/other/`: `pricing-api.yaml` (TLS with a PKCS12 truststore), `rest-mtls.yaml` (private CA
and a client certificate) and `rest-via-proxy.yaml` (a vendor API through the corporate proxy). There is no loader.

## Troubleshooting

- `failedToStart: … rest plugin needs settings.base-url`: set `base-url`.
- A service that is down does not change health (`UP`): it shows as failed reads, `reads.errors` and `lastError` in Admin → Health.
- `lastError` `… answered HTTP 401` / `403`: the token is missing, expired, or a placeholder sent as text.
- `lastError` names a JSON parse error: the service answered HTML (a login page, a redirect); point `base-url` at the final address.
- *No data available*: the service answered `2xx` with an empty body; it must answer `404` for unknown ids.
- `DRS-1004 timed out reading …`: raise `drishti.sources.fetch-timeout` and `timeout-ms` together.
- `%2F` ids answer `404`/`400`: the service or a proxy refuses encoded slashes; put the id in the query string.

Every case is in the full document, sections *Failure and recovery* and *Diagnosing*.
