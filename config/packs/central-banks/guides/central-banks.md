# The central-banks pack

**Policy rates and the market series around them**, part of the **public-sector module** (the Public sector lens): FRED (the Federal
Reserve Bank of St. Louis) for the Federal Reserve and US markets, the Bank of Canada's Valet API for Canada. The central-banks feed pulls
them daily into the `worldlake` lake.

| Type | Shows |
|---|---|
| `CBANK CBANK-FED <GO>` | the Federal Reserve: the target range's upper limit, the date and size of its last move, two years of the policy rate, every series of the bank with its latest value and change; its press releases one link away |
| `CBANK CBANK-BOC <GO>` | the Bank of Canada: the target for the overnight rate, CORRA, Canada's 2- and 10-year yields, USD/CAD |
| `CBSER CBSER-FRED-DGS10 <GO>` | one series: its history, the latest value, the change on the day and the year, the window's high and low |
| `CBNK <GO>` | the pack's overview |

**FRED needs a free API key**: register at https://fred.stlouisfed.org/docs/api/api_key.html and set `DRISHTI_FRED_API_KEY` where the feed
runs (never in a file). Without it the feed exits 3 and says so; the Bank of Canada's series need no key. The series are the feed's
selection (`config/feeds/central-banks.yaml`); a series of FRED with a third-party copyright needs its own internal-only flag there. The
domain, the lens, the feeds and their licences: the [Public sector guide](../../../../docs/guides/PUBLIC_SECTOR_GUIDE.md).

## Data contracts

Every kind of the pack has a data contract: a YAML file beside the pack (`config/packs/central-banks/contracts/<kind>.contract.yaml`, checked against `tools/contracts.schema.json`) that says what one record is, its key, how it is stored and dated, and every column. This section is generated from those files; the same files give the contract pages ([docs/contracts/packs/central-banks.md](../../../../docs/contracts/packs/central-banks.md), with each kind's validation rules and the points still to review). Check them against the pack and its data with `python3 tools/contracts.py check` (or `drishti.py contract check`); show one with `python3 tools/contracts.py show <MNEMONIC>`.

| Command | Kind | Class | Key | Grain | Columns |
|---|---|---|---|---|---|
| `CBANK` | `central-bank` | fundamental | `BANK_ID` | One row per central bank, keyed by BANK_ID. | 30 |
| `CBSER` | `rate-series` | fundamental | `SERIES_ID` | One row per central bank series, keyed by SERIES_ID. | 29 |

*Class*: **fundamental** data is delivered by a source system and stored; **input** is stored data an engine reads; **computed** is worked out by Drishti when asked and never stored by a source; **drishti-owned** is kept by Drishti itself.

## Data retrieval

Where each kind's data comes from, how it reaches the lake and how to check it. Three origins: **external** data, fetched from a public source by the pack's refresh script (each source, its licence and worked examples on the [External data](../../../../docs/guides/EXTERNAL_DATA.md) help page); **synthetic** test data (or hand-written reference data), written by a generator with fictitious names; **computed** by a Drishti engine when it is asked, never stored by a source.

| Command | Kind | Origin | How it reaches Drishti |
|---|---|---|---|
| `CBANK` | `central-bank` | external: FRED, Federal Reserve Bank of St. Louis (API key in DRISHTI_FRED_API_KEY) (FRED API terms; the default series are US government works (public domain)); Bank of Canada Valet API (Bank of Canada terms: free use with attribution) — refreshed by `drishti.py feed run central-banks` | the daily feed `central-banks` → `<data>/delta/worldlake/centralbank/central-bank/` (lake `worldlake`) → connector `centralbank-store`; nothing is committed but a few documents in `samples/` for the tests |
| `CBSER` | `rate-series` | external: FRED, Federal Reserve Bank of St. Louis (API key in DRISHTI_FRED_API_KEY) (FRED API terms; the default series are US government works (public domain)); Bank of Canada Valet API (Bank of Canada terms: free use with attribution) — refreshed by `drishti.py feed run central-banks` | the daily feed `central-banks` → `<data>/delta/worldlake/centralbank/rate-series/` (lake `worldlake`) → connector `centralbank-store`; nothing is committed but a few documents in `samples/` for the tests |

### External sources

| Source | Where | Licence | Internal only | Refresh |
|---|---|---|---|---|
| FRED, Federal Reserve Bank of St. Louis (API key in DRISHTI_FRED_API_KEY) | https://api.stlouisfed.org/fred | FRED API terms; the default series are US government works (public domain) | no | `python3 tools/drishti.py feed run central-banks` |
| Bank of Canada Valet API | https://www.bankofcanada.ca/valet | Bank of Canada terms: free use with attribution | no | `python3 tools/drishti.py feed run central-banks` |

```bash
python3 tools/drishti.py feed run central-banks --dry-run     # what the feed would pull; writes nothing
python3 tools/drishti.py feed run central-banks               # pull what is new into <data>/feeds/central-banks/<date>/ and load it (the parallel loader)
python3 tools/drishti.py feed run central-banks --load inbox  # the same through the data inbox: the server loads it
python3 tools/drishti.py feed status central-banks            # its last runs, rows and errors (the ledger)
```

The same through the wrappers: `tools/feeds/feed.sh run central-banks` on Linux and macOS, `.\tools\windows\feed.ps1 run central-banks` on Windows. The feed file is `config/feeds/central-banks.yaml` (its sources and their licences in `options.sources`, the schedule, the selection); the [Public sector guide](../../../../docs/guides/PUBLIC_SECTOR_GUIDE.md) and the [External data feeds guide](../../../../docs/guides/FEEDS_GUIDE.md) explain it.

### Into the lake, checking, offline

- **The lake.** `python3 tools/drishti.py lake demo` reads `data/testdata/testdata.yaml` and writes every dataset (test data, the packs' samples and the committed public-data snapshots) into `<data>/delta/<domain>/<kind>/`, where the pack's Delta connector serves it; a computed kind needs nothing loaded. `lake build` loads your own large JSON exports the same way ([Tools](../../../../docs/guides/TOOLS.md)).
- **Checking.** `python3 tools/contracts.py check` compares every contract with the pack and its data; each generator's `--check` (above) fails when the committed files differ from what it would write; in the console, `<MNEMONIC> <GO>` lists a kind and the pack's code opens its overview with the count of each kind.
- **Offline.** Everything committed works without a network: the test data, the samples and the public-data snapshots are in the repository and `lake demo` reads only them. A refresh script runs offline from its download cache (`--offline`); a connector that reaches the internet (news, yfinance, the public-data feeds) is off as shipped and never starts on a machine configured offline (`drishti.offline.plugins`).
