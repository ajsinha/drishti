# The world-development pack

World Bank **World Development Indicators** by country and year, part of the **public-sector module** (the Public sector lens). The
world-development feed pulls them daily from the World Bank's API into the `worldlake` lake; nothing is read live and nothing large is
committed.

| Type | Shows |
|---|---|
| `WDI WDI-CAN <GO>` | Canada's profile: region, income group, capital, population, GDP per head; every indicator's latest value (a row opens its history); the world map shaded by GDP per head (a country opens its profile) |
| `WDIS WDIS-IND-NY_GDP_MKTP_KD_ZG <GO>` | India's real GDP growth by year, with the World Bank's definition |
| `WDEV <GO>` | the pack's overview |

The indicators pulled are the feed's selection (`config/feeds/world-development.yaml`): population, GDP per head, GDP growth, inflation,
unemployment, life expectancy, poverty, access to electricity, internet use and central government debt, for every economy over fifteen
years. Add an indicator with one line there (its World Bank code, the profile field it fills and its unit). The domain, the lens, the
feeds and their licences: the [Public sector guide](../../../../docs/guides/PUBLIC_SECTOR_GUIDE.md).

## Data contracts

Every kind of the pack has a data contract: a YAML file beside the pack (`config/packs/world-development/contracts/<kind>.contract.yaml`, checked against `tools/contracts.schema.json`) that says what one record is, its key, how it is stored and dated, and every column. This section is generated from those files; the same files give the contract pages ([docs/contracts/packs/world-development.md](../../../../docs/contracts/packs/world-development.md), with each kind's validation rules and the points still to review). Check them against the pack and its data with `python3 tools/contracts.py check` (or `drishti.py contract check`); show one with `python3 tools/contracts.py show <MNEMONIC>`.

| Command | Kind | Class | Key | Grain | Columns |
|---|---|---|---|---|---|
| `WDI` | `development-profile` | fundamental | `PROFILE_ID` | One row per development profile, keyed by PROFILE_ID. | 35 |
| `WDIS` | `development-series` | fundamental | `SERIES_ID` | One row per development indicator series, keyed by SERIES_ID. | 25 |

*Class*: **fundamental** data is delivered by a source system and stored; **input** is stored data an engine reads; **computed** is worked out by Drishti when asked and never stored by a source; **drishti-owned** is kept by Drishti itself.

## Data retrieval

Where each kind's data comes from, how it reaches the lake and how to check it. Three origins: **external** data, fetched from a public source by its data feed (each source, its licence and worked examples on the [External data](../../../../docs/guides/EXTERNAL_DATA.md) help page); **synthetic** test data (or hand-written reference data), written by a generator with fictitious names; **computed** by a Drishti engine when it is asked, never stored by a source.

| Command | Kind | Origin | How it reaches Drishti |
|---|---|---|---|
| `WDI` | `development-profile` | external: World Bank World Development Indicators API (v2) (CC BY 4.0) — refreshed by `drishti.py feed run world-development` | the daily feed `world-development` → `<data>/delta/worldlake/development/development-profile/` (lake `worldlake`) → connector `development-store`; nothing is committed but a few documents in `samples/` for the tests |
| `WDIS` | `development-series` | external: World Bank World Development Indicators API (v2) (CC BY 4.0) — refreshed by `drishti.py feed run world-development` | the daily feed `world-development` → `<data>/delta/worldlake/development/development-series/` (lake `worldlake`) → connector `development-store`; nothing is committed but a few documents in `samples/` for the tests |

### External sources

| Source | Where | Licence | Internal only | Refresh |
|---|---|---|---|---|
| World Bank World Development Indicators API (v2) | https://api.worldbank.org/v2 | CC BY 4.0 | no | `python3 tools/drishti.py feed run world-development` |

```bash
python3 tools/drishti.py feed status world-development                  # its last runs: last success, rows, failures (offline: the run ledger)
python3 tools/drishti.py feed run world-development --dry-run           # what would be fetched and loaded; changes nothing
python3 tools/drishti.py feed run world-development                     # pull today's data and load it into the lake `worldlake` (what the daily schedule runs)
python3 tools/drishti.py feed run world-development --load inbox        # the same through the data inbox: the server loads it
python3 tools/drishti.py feed run world-development --since 2026-01-01  # pull again although the World Bank has not changed (after editing the indicators)
```

The same through the wrappers: `tools/feeds/feed.sh run world-development` on Linux and macOS, `.\tools\windows\feed.ps1 run world-development` on Windows (every argument is passed on); the daily schedule entries: `drishti.py feed schedule --cron` (or `--systemd`, `--windows`) ([FEEDS_GUIDE.md](../../../../docs/guides/FEEDS_GUIDE.md)).

### Into the lake, checking, offline

- **The lake.** `python3 tools/drishti.py lake demo` reads `data/testdata/testdata.yaml` and writes every dataset (test data, the packs' samples and the committed public-data snapshots) into `<data>/delta/<domain>/<kind>/`, where the pack's Delta connector serves it; a computed kind needs nothing loaded. `lake build` loads your own large JSON exports the same way ([Tools](../../../../docs/guides/TOOLS.md)).
- **Checking.** `python3 tools/contracts.py check` compares every contract with the pack and its data; each generator's `--check` (above) fails when the committed files differ from what it would write; in the console, `<MNEMONIC> <GO>` lists a kind and the pack's code opens its overview with the count of each kind.
- **Offline.** Everything committed works without a network: the test data, the samples and the public-data snapshots are in the repository and `lake demo` reads only them. A data feed runs offline from its download cache (`--offline`); a connector that reaches the internet (news, yfinance, the public-data feeds) is off as shipped and never starts on a machine configured offline (`drishti.offline.plugins`).
