# DuckDB connector templates

Ready-made connector files for the `duckdb` plugin: one file per banking data domain (`trading`, `reference`, `market`, `risk`,
`credit`, `collateral`), all reading the same DuckDB file, which `tools/load-duckdb.sh` writes.

## What it reads

Each file reads the table `<domain>.entities` of one DuckDB file and serves the kinds listed in it. All six share one read-only DuckDB
instance (one memory limit); the first connector on the file sets `memory-limit`, so the files give the same value. The reference kinds
are read in `effective` mode; every other kind in `snapshot` mode. Nothing is written. The files carry no promoted columns: add the
pack's `layout.<kind>.columns` to a copied file.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_DUCKDB_PATH` (`path`) | `${drishti.data.dir:./data}/duckdb/drishti.duckdb` | The DuckDB file; files with the same path share one instance |
| `DRISHTI_DUCKDB_MEMORY` (`memory-limit`) | `1GB` | DuckDB's native memory limit for the shared instance |
| `domain` | the file's domain (`trading`, …) | The data domain |
| `table` | `<domain>.entities` | The domain's table |
| `pool-size` | `8` for `trading-store`, `4` for the others | Reads of this connector at once |
| `mode.<kind>` | `effective` for the 12 reference kinds | How a date is read |

## Data structure

The file holds, per domain, the layout of the [duckdb connector README](../../../plugins/drishti-plugin-duckdb/README.md):
`<domain>.entities (kind, id, business_date, doc, promoted columns…)` written in `(kind, business_date, id)` order, and
`<domain>.entity_dates (kind, business_date, rows, loaded_at)`.

| Schema | Kinds the file serves |
|---|---|
| `trading` | `trade` |
| `reference` | `counterparty`, `counterparty-group`, `issuer`, `agreement`, `ccp`, `legal-entity`, `book`, `desk`, `trader`, `calendar`, `csa`, `clearing-account` |
| `market` | 20 kinds: curves (`ir-curve`, `repo-curve`, `fx-forward-curve`, `credit-curve`, …), surfaces, `fx-spot`, `equity`, `bond`, `rate-fixing`, `correlation-matrix` |
| `risk` | `var`, `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain` |
| `credit` | `netting-set`, `credit-limit`, `cva`, `sa-ccr` |
| `collateral` | `collateral-balance`, `margin-call`, `simm` |

## Examples

```bash
tools/load-duckdb.sh data/duckdb/drishti.duckdb                 # the samples: 1,791 documents x 10 business days
cp config/connectors.examples/duckdb/*-store.yaml config/connectors/
```

Set `DRISHTI_DUCKDB_PATH` when the file is elsewhere. `trading-store.yaml` is a single trade connector, while the trading pack routes
`trade` to `trade-endur`, `trade-calypso` and `trade-murex` as a union: save it as `trade-endur.yaml` (and the other two, each with
`union: "true"`), or keep one file and switch the other two off.

## Troubleshooting

- `DOWN: no DuckDB file at …`: run the loader, or set `DRISHTI_DUCKDB_PATH`.
- `UP (catalogue not refreshed: <domain>.entities is not in …)`: that domain was not loaded.
- On Windows a load cannot replace a file the server holds open: load into a new path and change `DRISHTI_DUCKDB_PATH`, or stop the
  server first.
