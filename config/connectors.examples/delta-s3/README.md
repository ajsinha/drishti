# Delta Lake on S3 connector templates

Ready-made connector files for **Delta Lake in AWS S3**: the `delta` plugin with its root in a bucket, `s3://<bucket>/<prefix>`, read
by the native engine (the AWS SDK, no Hadoop). The AWS side (the bucket, the lake's prefix, the IAM policy) is made, checked and
removed by [`deploy/aws/delta-s3/`](../../../deploy/aws/delta-s3/README.md); a production lake with KMS, a VPC endpoint, tiers and
alarms by [`deploy/aws/delta-lake/`](../../../deploy/aws/delta-lake/).

## What it reads

`risk-store.yaml` reads the market-risk pack's risk domain (P&L vectors, scenario PVs, the risk hierarchy, VaR limits, desk P&L) and
`trade-endur.yaml` the Endur trades (`table.trade: trade_endur`), each table at `s3://<bucket>/<prefix>/<domain>/<table>`, exactly the
layout of the local lake. Nothing is written by the server; the loaders write the same tables (`drishti.py lake build`, the parallel
loader with an `s3://` target).

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_DELTA_S3_BUCKET` | `drishti-lake` | The bucket (in `root`) |
| `DRISHTI_DELTA_S3_PREFIX` | `delta` | The lake's prefix in the bucket (in `root`) |
| `AWS_REGION` (`s3.region`) | `us-east-1` | The bucket's region |
| `domain` | `risk`, `trading` | The domain folder under the prefix |
| `engine` | `native` | The AWS SDK; `hadoop` (S3A) also reads `s3://` |
| `layout.<kind>.*`, `table.<kind>` | the packs' promoted columns, vectors, file layout and table names | As for every Delta connector |

Credentials come from the AWS default chain: on ECS the task role, else a profile or `AWS_ACCESS_KEY_ID`. No key is in the files; an
S3-compatible store (MinIO, Ceph) adds `s3.endpoint` and its keys as `${ENV}` references, as `other/customer-lake.yaml` does.

## Data structure

Each table is a Delta table (`_delta_log/` and Parquet files partitioned by `business_date`) in the delta connector's layout
([its README](../../../plugins/drishti-plugin-delta/README.md)): columns `id`, `doc`, `business_date` and the promoted fields.

| Under `s3://<bucket>/<prefix>/` | Tables (one per kind) |
|---|---|
| `risk/` | `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain`, `trade-valuation`, `portfolio`, `pnl-vector`, `scenario-pv`, `fx-scenario`, `scenario-set`, `risk-hierarchy`, `var-limit`, `desk-pnl`, `pnl-history` |
| `trading/` | `trade_endur` |

## Examples

```bash
deploy/aws/delta-s3/delta-s3.sh create --bucket acme-drishti-lake --prefix delta --role drishti-server
export DRISHTI_DELTA_S3_BUCKET=acme-drishti-lake DRISHTI_DELTA_S3_PREFIX=delta AWS_REGION=eu-west-2
cp config/connectors.examples/delta-s3/risk-store.yaml config/connectors/
deploy/aws/delta-s3/delta-s3.sh check --table risk/pnl-vector
```

## Troubleshooting

- `DOWN: cannot reach s3://…`: credentials, region or bucket; `delta-s3.sh check` names the step.
- `no table …`: the loader has not written that kind under `s3://<bucket>/<prefix>/<domain>/`.
- `AccessDenied` on a write: the server's policy is read-only (`--read-only`); the loader needs the read-write one.
