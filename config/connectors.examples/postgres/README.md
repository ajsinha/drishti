# PostgreSQL connector templates

Ready-made connector files for the `jdbc` plugin in table mode: one file per banking data domain (`trading`, `reference`, `market`,
`risk`, `credit`, `collateral`), all reading one PostgreSQL database that `tools/load-postgres.sh` fills.

## What it reads

Each file reads one schema of the database, the table `<domain>.entities`, and serves the kinds listed in it. The reference kinds
are read in `effective` mode (a row when an entity changes); every other kind in `snapshot` mode (every entity every day). Nothing is
written. The files carry no promoted columns: a pack's `layout.<kind>.columns` must be added to a copied file, since a file replaces
the pack's template wholesale.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_PG_URL` (`url`) | `jdbc:postgresql://localhost:5432/drishti` | The JDBC URL; never put a password in it |
| `DRISHTI_PG_USER` (`user`) | `drishti` | The database user (needs `SELECT` only) |
| `DRISHTI_PG_PASSWORD` (`password`) | none: must be set | The password, from the environment (or replace with `file:/path`) |
| `domain` | the file's domain (`trading`, …) | The data domain |
| `table` | `<domain>.entities` | The domain's table; setting it turns table mode on |
| `mode.<kind>` | `effective` for the 12 reference kinds | How a date is read |
| `pool-size` | the site's `drishti.db.pool.size` (20), commented out | Uncomment to size one connector's pool |

## Data structure

The database holds, per domain, the table mode layout (see the [jdbc connector README](../../../plugins/drishti-plugin-jdbc/README.md)):
`<domain>.entities (kind, id, business_date, doc jsonb, promoted columns…)`, partitioned by month on `business_date`, primary key
`(kind, id, business_date)`, the index `(kind, business_date, id)`, and `<domain>.entity_dates (kind, business_date, rows, loaded_at)`.

| Schema | Kinds the file serves |
|---|---|
| `trading` | `trade` |
| `reference` | `counterparty`, `counterparty-group`, `issuer`, `agreement`, `ccp`, `legal-entity`, `book`, `desk`, `trader`, `calendar`, `csa`, `clearing-account` |
| `market` | 20 kinds: curves (`ir-curve`, `repo-curve`, `fx-forward-curve`, `credit-curve`, …), surfaces, `fx-spot`, `equity`, `bond`, `rate-fixing`, `correlation-matrix` |
| `risk` | `var`, `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain` |
| `credit` | `netting-set`, `credit-limit`, `exposure-profile`, `cva`, `sa-ccr` |
| `collateral` | `collateral-balance`, `margin-call`, `simm` |

## Examples

```bash
export DRISHTI_PG_URL=jdbc:postgresql://db.example.com:5432/drishti DRISHTI_PG_USER=drishti DRISHTI_PG_PASSWORD=...
tools/load-postgres.sh "$DRISHTI_PG_URL"                       # the samples: 1,791 documents x 10 business days
cp config/connectors.examples/postgres/risk-store.yaml config/connectors/
```

The server starts the copied connector within seconds. `trading-store.yaml` is a single trade connector, while the trading pack routes
`trade` to `trade-endur`, `trade-calypso` and `trade-murex` as a union: save it as `trade-endur.yaml` (and the other two, each with
`union: "true"`), or keep one file and switch the other two off.

## Troubleshooting

- `DOWN: <driver message> (reconnecting)`: the database is unreachable or `DRISHTI_PG_PASSWORD` is not set or wrong.
- `UP (catalogue not refreshed: …)`: the schema or table is missing; load that domain with `tools/load-postgres.sh`.
- `UP (not laid out as the pack declares: …; searches read documents)`: add the pack's `layout.<kind>.columns` and reload.
- Trades still come from Delta: the trading pack does not read `trading-store`; see the note above.
