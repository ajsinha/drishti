# MongoDB connector templates

Ready-made connector files for the `mongodb` plugin: one file per banking data domain (`trading`, `reference`, `market`, `risk`,
`credit`, `collateral`), all reading one database that `tools/load-mongodb.sh` fills.

## What it reads

Each file reads the collections `<domain>` and `<domain>_columns` of the database and serves the kinds listed in it. The reference
kinds are read in `effective` mode; every other kind in `snapshot` mode. Nothing is written. The files carry no promoted columns: add
the pack's `layout.<kind>.columns` to a copied file for fast searches.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_MONGODB_URI` (`uri`) | `mongodb://localhost:27017` | The connection string; a password in it only as an `${ENV}` reference |
| `DRISHTI_MONGODB_DATABASE` (`database`) | `drishti` | The database |
| `domain` | the file's domain (`trading`, …) | The data domain, which names the collections |
| `mode.<kind>` | `effective` for the 12 reference kinds | How a date is read |

## Data structure

The database holds, per domain, the collections of the [mongodb connector README](../../../plugins/drishti-plugin-mongodb/README.md):
`<domain>` (a document per entity per day, `_id` `kind/id/yyyyMMdd`, fields `kind`, `id`, `date`, `doc`, `c`) and
`<domain>_columns` (`kind`, `id`, `date`, `c`), each with the index `day_ids` `{kind: 1, date: 1, id: 1}`.

| Collections | Kinds the file serves |
|---|---|
| `trading`, `trading_columns` | `trade` |
| `reference`, `reference_columns` | `counterparty`, `counterparty-group`, `issuer`, `agreement`, `ccp`, `legal-entity`, `book`, `desk`, `trader`, `calendar`, `csa`, `clearing-account` |
| `market`, `market_columns` | 20 kinds: curves (`ir-curve`, `repo-curve`, `fx-forward-curve`, `credit-curve`, …), surfaces, `fx-spot`, `equity`, `bond`, `rate-fixing`, `correlation-matrix` |
| `risk`, `risk_columns` | `var`, `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain` |
| `credit`, `credit_columns` | `netting-set`, `credit-limit`, `exposure-profile`, `cva`, `sa-ccr` |
| `collateral`, `collateral_columns` | `collateral-balance`, `margin-call`, `simm` |

## Examples

```bash
export DRISHTI_MONGODB_URI=mongodb://db.example.com:27017 DRISHTI_MONGODB_DATABASE=drishti
tools/load-mongodb.sh "$DRISHTI_MONGODB_URI" "$DRISHTI_MONGODB_DATABASE"     # the samples: 1,791 documents x 10 business days
cp config/connectors.examples/mongodb/*-store.yaml config/connectors/
```

`trading-store.yaml` is a single trade connector, while the trading pack routes `trade` to `trade-endur`, `trade-calypso` and
`trade-murex` as a union: save it as `trade-endur.yaml` (and the other two, each with `union: "true"`), or keep one file and switch the
other two off. Over TLS, see `config/connectors.examples/other/positions-mongo.yaml`.

## Troubleshooting

- `DOWN: cannot reach MongoDB (…)`: check `DRISHTI_MONGODB_URI` and that the server runs.
- `DOWN: no documents in drishti.<domain>`: that domain was not loaded, or `DRISHTI_MONGODB_DATABASE` is another database.
- `UP (not laid out: missing index day_ids …)`: the collections were written by another tool; create the index or reload.
