# Redis connector templates

Ready-made connector files for the `redis` plugin: one file per banking data domain (`trading`, `reference`, `market`, `risk`,
`credit`, `collateral`), all reading one Redis that `tools/load-redis.sh` fills.

## What it reads

Each file reads the keys under the prefix `<domain>:` and serves the kinds listed in it, with live updates on `<domain>:changes`
(`live` is on by default). The reference kinds are read in `effective` mode; every other kind in `snapshot` mode. Nothing is written.
The files carry no promoted columns: add the pack's `layout.<kind>.columns` to a copied file for fast searches.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_REDIS_URI` (`uri`) | `redis://localhost:6379` | The Redis address; `rediss://` for TLS; several, comma separated, for Cluster seeds |
| `DRISHTI_REDIS_CLUSTER` (`cluster`) | `false` | `true` for Redis Cluster |
| `domain` | the file's domain (`trading`, …) | The key prefix |
| `mode.<kind>` | `effective` for the 12 reference kinds | How a date is read |

A password is not in the files; add `password: ${…}` (an environment or `file:` reference) for a server that needs one.

## Data structure

Redis holds, per domain, the keys of the [redis connector README](../../../plugins/drishti-plugin-redis/README.md): `<domain>:kinds`,
`<domain>:<kind>:days`, `{<domain>:<kind>:days}:gens`, `<domain>:<kind>:{<id>}` and its documents `…:{<id>}:<yyyyMMdd>.<g>`, the day's
column hash `{<domain>:<kind>:<yyyyMMdd>}:cols:<g>`, the zstd dictionaries `<domain>:dict:<id>`, `<domain>:updated` and the channel
`<domain>:changes`.

| Prefix | Kinds the file serves |
|---|---|
| `trading:` | `trade` |
| `reference:` | `counterparty`, `counterparty-group`, `issuer`, `agreement`, `ccp`, `legal-entity`, `book`, `desk`, `trader`, `calendar`, `csa`, `clearing-account` |
| `market:` | 20 kinds: curves (`ir-curve`, `repo-curve`, `fx-forward-curve`, `credit-curve`, …), surfaces, `fx-spot`, `equity`, `bond`, `rate-fixing`, `correlation-matrix` |
| `risk:` | `var`, `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain` |
| `credit:` | `netting-set`, `credit-limit`, `exposure-profile`, `cva`, `sa-ccr` |
| `collateral:` | `collateral-balance`, `margin-call`, `simm` |

## Examples

```bash
export DRISHTI_REDIS_URI=redis://cache.example.com:6379
tools/load-redis.sh "$DRISHTI_REDIS_URI"                     # the samples: 1,791 documents x 10 business days
cp config/connectors.examples/redis/*-store.yaml config/connectors/
```

`trading-store.yaml` is a single trade connector, while the trading pack routes `trade` to `trade-endur`, `trade-calypso` and
`trade-murex` as a union: save it as `trade-endur.yaml` (and the other two, each with `union: "true"`), or keep one file and switch the
other two off. Over TLS, see `config/connectors.examples/other/redis-tls.yaml`.

## Troubleshooting

- `DOWN: cannot reach Redis at redis://…`: check `DRISHTI_REDIS_URI`, credentials and `rediss://` for TLS.
- A day is not served: its load has not finished (columns are written at the end).
- Open views do not tick: load with `--publish`.
