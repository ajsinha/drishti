# S3 Tables connector templates

Ready-made connector files for **AWS S3 Tables**: the `iceberg` plugin with `catalog: s3tables`, which reads (and, for the loaders,
writes) Iceberg tables in an S3 table bucket through the S3 Tables Iceberg REST endpoint, every request signed with SigV4. One
setting names the table bucket, its ARN; everything else follows from it. The AWS side (the table bucket, the namespace, the IAM
policy) is made, checked and removed by [`deploy/aws/s3-tables/`](../../../deploy/aws/s3-tables/README.md).

## What it reads

`risk-store.yaml` reads the market-risk pack's risk domain (P&L vectors, scenario PVs, the risk hierarchy, VaR limits, desk P&L) and
`trade-endur.yaml` the Endur trades, each from one namespace of the table bucket: the domain (`risk`, `trading`) as an S3 Tables name.
A kind is read from the table of its name with hyphens made underscores (`pnl-vector` is the table `pnl_vector`), because S3 Tables
allows lower-case letters, digits and underscores only. Nothing is written by the server; the loaders write the same tables
(`drishti.py lake build --format iceberg`, the parallel loader with `target.iceberg`) with the same settings.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `catalog` | `s3tables` | AWS S3 Tables through its Iceberg REST endpoint |
| `DRISHTI_S3TABLES_ARN` (`table-bucket-arn`) | empty: the connector stays idle until it is set | The table bucket, `arn:aws:s3tables:<region>:<account>:bucket/<name>` |
| `domain` | `risk`, `trading` | The namespace (as an S3 Tables name) |
| `engine` | `native` | S3 Tables is read by the native engine only |
| `uri` | `https://s3tables.<region>.amazonaws.com/iceberg`, from the ARN | Give it for a VPC interface endpoint |
| `layout.<kind>.*` | the packs' promoted columns, vectors and file layout | As for every Iceberg connector |

The region, the SigV4 signing name `s3tables`, the warehouse (the ARN), the REST path prefix and `vended-credentials: false` follow
from the ARN. Credentials come from the AWS default chain: on ECS the task role, else a profile or `AWS_ACCESS_KEY_ID`. No key is in
the files.

## Data structure

The namespace holds one Iceberg table per kind in the iceberg connector's layout
([its README](../../../plugins/drishti-plugin-iceberg/README.md)): columns `id`, `doc`, `business_date` and the promoted fields,
partitioned by `identity(business_date)`, sorted by `id`; vectors as `list<double>`.

| Namespace | Tables (one per kind) |
|---|---|
| `risk` | `stress_scenario`, `stress_result`, `frtb_sensitivity`, `pnl_explain`, `trade_valuation`, `portfolio`, `pnl_vector`, `scenario_pv`, `fx_scenario`, `scenario_set`, `risk_hierarchy`, `var_limit`, `desk_pnl`, `pnl_history` |
| `trading` | `trade` |

## Examples

```bash
deploy/aws/s3-tables/s3-tables.sh create --bucket drishti-risk --namespace risk --role drishti-server
export DRISHTI_S3TABLES_ARN=arn:aws:s3tables:eu-west-2:123456789012:bucket/drishti-risk
cp config/connectors.examples/s3tables/risk-store.yaml config/connectors/
deploy/aws/s3-tables/s3-tables.sh check --bucket drishti-risk --namespace risk --table pnl-vector
```

## Troubleshooting

- Idle with `needs settings.table-bucket-arn`: `DRISHTI_S3TABLES_ARN` is not set.
- `HTTP 403` from `s3tables.<region>.amazonaws.com`: the principal lacks the policy of `s3-tables.sh create` (`s3tables:Get*`,
  `s3tables:GetTableData`); `s3-tables.sh check` names the step.
- `no table pnl_vector`: the loader has not written that kind yet, or wrote it under another namespace.
- `engine: library` is refused: S3 Tables is read by the native engine.
