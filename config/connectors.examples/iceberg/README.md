# Iceberg connector templates

Ready-made connector files for the `iceberg` plugin: one file per banking data domain (`reference`, `market`, `risk`, `credit`,
`collateral`) and `trade-endur.yaml` for the trades, all reading tables that `tools/load-iceberg.sh` (or
`tools\windows\load-iceberg.ps1`) writes. `tools\windows\start-server.ps1 -Iceberg` copies them in.

## What it reads

Each file reads the tables of one domain: `<root>/<domain>/<kind>` with the default `catalog: hadoop`, or the namespace `<domain>` of a
REST catalog with `catalog: rest`. The reference kinds are read in `effective` mode; every other kind in `snapshot` mode. Nothing is
written. `trade-endur.yaml` also carries the trading pack's promoted columns and file layout for `trade`; the domain files carry none.

## Settings

| Setting or variable | Default in the files | Meaning |
|---|---|---|
| `DRISHTI_ICEBERG_ROOT` (`root`) | `${drishti.data.dir:./data}/iceberg` | The warehouse root for path-based tables (a folder or `s3://…`) |
| `DRISHTI_ICEBERG_CATALOG` (`catalog`) | `hadoop` | `hadoop` (path-based) or `rest` |
| `DRISHTI_ICEBERG_URI` (`uri`) | empty | A REST catalog's URI |
| `DRISHTI_ICEBERG_WAREHOUSE` (`warehouse`) | empty | A REST catalog's warehouse |
| `DRISHTI_ICEBERG_CREDENTIAL` (`credential`) | empty | A REST catalog's OAuth2 `id:secret`, from the environment |
| `domain` | the file's domain (`trading`, …) | The domain folder, or the catalog namespace |
| `mode.<kind>` | `effective` for the 12 reference kinds | How a date is read |
| `layout.trade.*` | `trade-endur.yaml` only: 16 promoted columns, `sort-by: id`, `file-rows: 250000`, `row-group-rows: 1000` | The trade table's layout |

## Data structure

The root (or catalog) holds one Iceberg table per kind, in the layout of the
[iceberg connector README](../../../plugins/drishti-plugin-iceberg/README.md): columns `id`, `doc`, `business_date` and the promoted
fields, partitioned by `identity(business_date)`, sorted by `id`.

| Folder or namespace | Tables (one per kind) |
|---|---|
| `trading` | `trade` |
| `reference` | `counterparty`, `counterparty-group`, `issuer`, `agreement`, `ccp`, `legal-entity`, `book`, `desk`, `trader`, `calendar`, `csa`, `clearing-account` |
| `market` | 20 kinds: curves (`ir-curve`, `repo-curve`, `fx-forward-curve`, `credit-curve`, …), surfaces, `fx-spot`, `equity`, `bond`, `rate-fixing`, `correlation-matrix` |
| `risk` | `var`, `stress-scenario`, `stress-result`, `frtb-sensitivity`, `pnl-explain` |
| `credit` | `netting-set`, `credit-limit`, `exposure-profile`, `cva`, `sa-ccr` |
| `collateral` | `collateral-balance`, `margin-call`, `simm` |

## Examples

```bash
tools/load-iceberg.sh ./data/iceberg                        # the samples: 1,791 documents x 10 business days
cp config/connectors.examples/iceberg/*.yaml config/connectors/
```

For a REST catalog set `DRISHTI_ICEBERG_CATALOG=rest`, `DRISHTI_ICEBERG_URI`, `DRISHTI_ICEBERG_WAREHOUSE` and
`DRISHTI_ICEBERG_CREDENTIAL`. The trading pack routes `trade` to `trade-endur`, `trade-calypso` and `trade-murex` as a union:
`trade-endur.yaml` replaces the first of those Delta connectors; the other two stay as they are unless you add files for them too.

## Troubleshooting

- `DOWN: no Iceberg tables under …`: that domain was not loaded, or `DRISHTI_ICEBERG_ROOT` points elsewhere.
- `DOWN: cannot reach …`: the root, bucket or catalog is not reachable; check the variables above and `s3.*`.
- On Windows keep the default `engine: native`; `engine: library` needs `winutils.exe`.
