What is {{ PRODUCT }}

{{ PRODUCT }} ({{ PRODUCT_NATIVE or 'दृष्टि' }}, Sanskrit for sight) lets a person see a trade, a patient, a gene or an economy the same way: one live page, linked to what it relates to, showing only what that person may see. A short screen grammar called Rachana describes a view, a Sutra is a screen written in it, and inference completes whatever a Sutra leaves out.

The problem it solves

Every system has its own screens, built one by one, in their own style, with their own access rules. Adding a source means a project, and the figures on a page rarely say what they mean or where they came from. {{ PRODUCT }} replaces the per-product screen with a grammar: connect the data, and views, search, reports and alerts come with it, masked the same way everywhere.

Key features

The command line

Type a mnemonic and a key (TRD MX-20000001, CPTY, HELP) with suggestions as you type; every screen is reachable from the keyboard.

Sutras and the Build workbench

A screen is a short Rachana (Sutra) file; the Build workbench designs, tests, versions and ships them without code.

Query by form

Filter, sort and pick from a form with the same power as the command line.

Live updates

Views tick as the data changes; only what changed is sent.

Any connector as a file

Add a database, lake or message source from a file: TLS, proxy and secrets are settings and no restart is needed.

Domain packs

Core reference data, market data, trading, counterparty and market risk, the world economy and news arrive as packs with their own Sutras, words and sample data.

Masks and roles everywhere

One mask decides what each person sees, in views, search, exports, reports, notebooks and the AI layer.

Share, discuss, inbox

Send a view or a finding, comment on it, and keep an inbox of what concerns you.

Reports and subscriptions

Scheduled and on-demand reports, with subscriptions per person.

Rupaka BI

Datasets, reports, a designer, governance and review, live boards, Python measures and visuals, and Analyse for notebooks.

Alerts

Rules over live data raise alerts that reach the inbox, with history.

AI layer

Off by default; when on, it sees only what the person may see and answers with masked data.

Drishti Elements

Embed a view, a report or a panel in another web page with one tag.

Real public data

Economics, politics and other packs load real public series, with their sources named in the glossary.

Competitive advantage

Terminals show market data, platform screens show one vendor's trades, low-code tools need a screen built per table, and BI tools stop at the chart. {{ PRODUCT }} is one grammar for all of them: live, linked, masked, self-hosted and keyboard-first.

Read the competitive analysis

Technology stack

  • Server: one Spring Boot 3.5 application on Java 21 or newer with virtual threads; a Spring-free plugin SPI for sources; DuckDB for BI queries.
  • Console: FastAPI and server-rendered pages; Bootstrap, Bootstrap Icons, ECharts, Perspective, CodeMirror and Pyodide, all vendored.
  • Security: a strict content-security policy with no inline script or style, so it runs air-gapped; roles and masks enforced on the server.

Use cases

  • Trading desks. Trades, positions and P&L as linked live views, with the netting set one key away.
  • Risk. Limits, VaR and exposure with the figures explained in the page's own words.
  • Operations. Loads, breaks and queues watched live, with alerts and an inbox.
  • Public data. Economics and politics series for research, with sources named.
  • Anywhere data lives. Point a connector at a system and get views the same day, with no screen coded.
