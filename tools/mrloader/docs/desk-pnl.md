# desk-pnl: Desk P&L: actual and hypothetical (daily) (from CSV)

*Generated by `tools/mrloader/kind_docs.py` from the kind's contract, its mapping file and its sample: do not edit; change the mapping or the contract and run it again.*

## 1. What it is and who reads it

Each desk's actual (clean) and hypothetical P&L of the day, in USD, for the VaR backtest: one row per desk and legal entity.

The bank's daily P&L of each desk for regulatory backtesting (VAR_GUIDE.md section 15.16): the actual P&L from finance (clean: fees, commissions, reserves, net interest income and intraday trading left out) and the hypothetical P&L from front office (yesterday's positions revalued on today's market), in USD. Never an input of the VaR engine: the backtest compares the official VaR of the day before with them. Drishti's own risk-theoretical P&L (the official record's hypoPnl) is not this kind.

- **Contract:** `modules/banking/packs/market-risk/contracts/desk-pnl.contract.yaml` (pack `market-risk`, class `input`), key `DESK_PNL_ID`.
- **Mapping:** `tools/mrloader/kinds/desk-pnl.yaml` (source `canonical`); wave 1 of the CSV loaders.
- **Grain:** One row per desk (and its legal entity) per BUSINESS_DATE, keyed by DESK_PNL_ID (DPNL-<DESK_ID>-<BUSINESS_DATE>).

## 2. The command

```bash
python3 tools/mrloader/csv_load.py --kind desk-pnl --csv FILE --date YYYY-MM-DD --dry-run   # check; write nothing
python3 tools/mrloader/csv_load.py --kind desk-pnl --csv FILE --date YYYY-MM-DD --inbox     # convert and hand to the data inbox
python3 tools/mrloader/csv_load.py --kind desk-pnl --template                                       # the header and an example row
```

In a day file: `desk-pnl: {csv: "FILE"}`. A bank's own column names: a mapping file of its own, given with `--mapping FILE`.

## 3. The CSV, column by column

The file's format: delimiter `,`, encoding `utf-8`, decimal `.`, thousands `,`, dates `YYYY-MM-DD` (declared in the mapping's `csv:` block over `kinds/shared/csv.yaml`; never guessed). Column names compare upper-cased, other characters as `_`.

| Column | Required | Field | Rule | Description | Decision |
|---|---|---|---|---|---|
| `DESK_ID` | yes | `DESK_ID` | upper-cased, other characters `-`; prefixed `DESK-` unless it has it; text, kept as written | The desk: the id of a desk node of the hierarchies (DESK-RATES is the node MGMT~DESK-RATES). A node's P&L is the sum of its desks' rows; the bank's, of every row. |  |
| `LEGAL_ENTITY` | no | `LEGAL_ENTITY` | upper-cased, other characters `-`; prefixed `LE-` unless it has it; text, kept as written | The legal entity the desk's P&L is booked in: the LEGAL hierarchy's nodes sum the rows of their entity. |  |
| (none) | no | `DESK_PNL_ID` | built: `DPNL-{@DESK_ID}-{$business_date}`; text, kept as written | The record's id, DPNL-<DESK_ID>-<BUSINESS_DATE> (the business key) |  |
| (none) | no | `BUSINESS_DATE` | built: `{$business_date}`; a date (YYYY-MM-DD, or YYYYMMDD) | The business date the P&L is of (YYYY-MM-DD): the day the market moved, tested against the official VaR of the business day before. |  |
| `ACTUAL_PNL` | yes | `ACTUAL_PNL` | a number (decimal `.`) | Finance's clean actual P&L of the day: fees, commissions, reserves, net interest income and intraday trading left out (US 12 CFR 217.204(b); OSFI CAR chapter 9). Negative is a loss. | signed: a loss is negative; never zero for a missing value |
| `HYPOTHETICAL_PNL` | yes | `HYPOTHETICAL_PNL` | a number (decimal `.`) | Front office's hypothetical P&L of the day: the end of the day before's positions revalued on the day's market, nothing traded. Negative is a loss. |  |
| `FEES_AND_COMMISSIONS` | no | `FEES_AND_COMMISSIONS` | a number (decimal `.`) | What finance left out of ACTUAL_PNL (fees, commissions, reserves), for the record: never part of a backtest. |  |
| `CURRENCY` | no | `CURRENCY` | upper-cased; empty: `USD` | The currency of the amounts, ISO 4217: USD. |  |
| `SOURCE` | yes | `SOURCE` | as written | The system the row came from (the finance ledger or the front-office P&L system); demo-finance on the test data. |  |
| `AS_OF` | no | `AS_OF` | empty: `{$computed_at}`; ISO-8601 with a zone | When the source produced the figures (UTC). A restated day is sent again with a later AS_OF; the lake's newest row wins. |  |

## 5. What is not loaded

Nothing: every field the CSV gives is loaded.

## 6. Checks

- **A rejected row:** `on-reject: refuse` (any rejected row refuses the whole kind: fix the file and run again). A duplicate key always refuses it.
- **Unique:** `DESK_PNL_ID` per business date.
- **Link** `LEGAL_ENTITY` to `legal-entity`: policy `warn` (mr_run.py checks it against the day's `legal-entity` file, else `--against`; a target found nowhere is *not checked*).
- **Link** `DESK_ID` to `desk`: policy `warn` (mr_run.py checks it against the day's `desk` file, else `--against`; a target found nowhere is *not checked*).

Reject codes it can give: `MISSING_REQUIRED`, `BAD_DATE`, `BAD_NUMBER`, `BAD_TIMESTAMP`, `EXCEL_NUMBER_ID`, `BAD_ENUM`, `BAD_PATTERN`, `DUPLICATE_KEY`, `EXCEL_ERROR`, `FORMULA`, `BAD_ROW_SHAPE`.
Each line of `<kind>.<date>.rejects.csv` gives FILE, ROW (as a spreadsheet shows it), KEY, COLUMN, FIELD, VALUE, REASON, WHY, FIX.

## 7. Before and after

- **Load first:** `desk`.
- **Then:** nothing depends on it.

## 8. Repeat, restate, remove

- **Again for the same date:** the same command; the date's `desk-pnl` rows are replaced as a whole (`mode: replace`).
- **Restate a past date:** run with that `--date`; to change one row, send the whole file again.
- **Remove the date:** `python3 tools/drishti.py lake delete --lake LAKE --kind desk-pnl --date YYYY-MM-DD --dry-run` (then without `--dry-run`).

## 9. Spreadsheet warnings

- `DESK_ID`: an id: export the column as text (a long id saved as a number, `2.00001E+11`, is refused; leading zeros lost are not detectable without `pad:`)
- `LEGAL_ENTITY`: an id: export the column as text (a long id saved as a number, `2.00001E+11`, is refused; leading zeros lost are not detectable without `pad:`)

## 10. Source variants

None shipped. A source with other column names gets a mapping file `kinds/desk-pnl.<source>.yaml` (or a site's own, by `--mapping`).
