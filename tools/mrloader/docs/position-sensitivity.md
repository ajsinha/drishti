# position-sensitivity: Position sensitivities (from CSV)

*Generated by `tools/mrloader/kind_docs.py` from the kind's contract, its mapping file and its sample: do not edit; change the mapping or the contract and run it again.*

## 1. What it is and who reads it

The sensitivities of each position (or trade) to its risk factors, from the bank's risk run: one record a position, its sensitivities a list.

The first-order and curvature sensitivities of each position (or trade) to the standard risk factors, as the bank's pricing or risk system computes them after the close: rate, inflation and credit-spread sensitivities per basis point, spot and price deltas per one per cent, vegas per volatility point, and the curvature results of the regulatory shocks. One table feeds the FRTB standardised approach (the sensitivities-based method, Basel MAR21), ISDA SIMM, the MR cube's ladders and heat maps, sensitivity limits and P&L explain. Read by the server's FRTB-SA engine (docs/guides/FRTB_SA_GUIDE.md); SENS <scope> sums it by factor or bucket.

- **Contract:** `modules/banking/packs/market-risk/contracts/position-sensitivity.contract.yaml` (pack `market-risk`, class `input`), key `SENSITIVITY_ID`.
- **Mapping:** `tools/mrloader/kinds/position-sensitivity.yaml` (source `canonical`); wave 1 of the CSV loaders.
- **Grain:** One record per position (GRAIN POSITION) or trade (GRAIN TRADE), business date and batch, keyed by SENSITIVITY_ID (SENS-<POSITION_ID or TRADE_ID>-<BATCH_ID>); its sensitivities a sparse list, one element per risk factor and measure.

## 2. The command

```bash
python3 tools/mrloader/csv_load.py --kind position-sensitivity --csv FILE --child SENSITIVITIES=FILE --source-system SYSTEM --date YYYY-MM-DD --dry-run   # check; write nothing
python3 tools/mrloader/csv_load.py --kind position-sensitivity --csv FILE --child SENSITIVITIES=FILE --source-system SYSTEM --date YYYY-MM-DD --inbox     # convert and hand to the data inbox
python3 tools/mrloader/csv_load.py --kind position-sensitivity --template                                       # the header and an example row
```

In a day file: `position-sensitivity: {csv: "FILE", child: {SENSITIVITIES: "FILE"}}`. A bank's own column names: a mapping file of its own, given with `--mapping FILE`.

## 3. The CSV, column by column

The file's format: delimiter `,`, encoding `utf-8`, decimal `.`, thousands `,`, dates `YYYY-MM-DD` (declared in the mapping's `csv:` block over `kinds/shared/csv.yaml`; never guessed). Column names compare upper-cased, other characters as `_`.

| Column | Required | Field | Rule | Description | Decision |

## 5. What is not loaded

Nothing: every field the CSV gives is loaded.

## 6. Checks

- **A rejected row:** `on-reject: skip`, `max-rejects: 1%` (rejected rows are listed and the rest loads). A duplicate key always refuses it.
- **Unique:** `SENSITIVITY_ID` per business date.
- **When** {"GRAIN": "POSITION"}: `POSITION_ID` needed (CONDITION).
- **When** {"GRAIN": "TRADE"}: `TRADE_ID` needed (CONDITION).
- **When** {"SENSITIVITIES[].MEASURE": ["CURVATURE_UP", "CURVATURE_DOWN"]}: `SENSITIVITIES[].SHOCK_SIZE` needed (CONDITION).
- **One value a date:** `BATCH_ID`.
- **Link** `LEGAL_ENTITY` to `legal-entity`: policy `warn` (mr_run.py checks it against the day's `legal-entity` file, else `--against`; a target found nowhere is *not checked*).
- **Link** `DESK` to `desk`: policy `warn` (mr_run.py checks it against the day's `desk` file, else `--against`; a target found nowhere is *not checked*).
- **Link** `TT_BOOK` to `book`: policy `warn` (mr_run.py checks it against the day's `book` file, else `--against`; a target found nowhere is *not checked*).
- **Link** `SENSITIVITIES[].RISK_FACTOR` to `risk-factor`: policy `warn` (mr_run.py checks it against the day's `risk-factor` file, else `--against`; a target found nowhere is *not checked*).
- **Link** `POSITION_ID` to `scenario-pv`: policy `warn` (mr_run.py checks it against the day's `scenario-pv` file, else `--against`; a target found nowhere is *not checked*).

Reject codes it can give: `MISSING_REQUIRED`, `BAD_DATE`, `BAD_INTEGER`, `BAD_NUMBER`, `BAD_TIMESTAMP`, `EXCEL_NUMBER_ID`, `BAD_ENUM`, `BAD_PATTERN`, `DUPLICATE_KEY`, `EXCEL_ERROR`, `FORMULA`, `BAD_ROW_SHAPE`.
Each line of `<kind>.<date>.rejects.csv` gives FILE, ROW (as a spreadsheet shows it), KEY, COLUMN, FIELD, VALUE, REASON, WHY, FIX.

## 7. Before and after

- **Load first:** `risk-factor`, `scenario-pv`.
- **Then:** nothing depends on it.

## 8. Repeat, restate, remove

- **Again for the same date:** the same command; the date's `position-sensitivity` rows are replaced as a whole (`mode: replace`).
- **Restate a past date:** run with that `--date` and `--restatement 1` (then 2 ...); to change one row, send the whole file again.
- **Remove the date:** `python3 tools/drishti.py lake delete --lake LAKE --kind position-sensitivity --date YYYY-MM-DD --dry-run` (then without `--dry-run`).
